# inkloom P1-c 实现计划（HTTP API + 前端）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把已经在 CLI 里验证过的"生成 → 审阅 → 定稿"能力，变成浏览器里能点的一页纸——让你亲手操作一遍，从而发现任何测试都替代不了的真问题。

**Architecture:** 分两段。先补 HTTP 层（Hono），把 service 函数原样暴露成 REST，**不做多书并发**（Ruling 45）；再做前端（React 19 + Vite + Tailwind + TanStack Query + Zustand），页面只有一个：写作页。叙事地图用 `@xyflow/react` + `dagre`（spec §4.15 指定）。

**Tech Stack:** Hono 4（已装）+ `@hono/node-server` / React 19 + Vite 7 + Tailwind 4 + `@tanstack/react-query` + `zustand` + `@xyflow/react` + `dagre`

**Spec:** `docs/superpowers/specs/2026-10-25-inkloom-design.md` §4.15（四个核心视图与选型）、Stage 1–4（界面深度）、§7（错误处理）

## Global Constraints

| 约束 | 值 / 规则 | 出处 |
|---|---|---|
| 单书模式 | 服务启动时绑定一本书（`INKLOOM_BOOK`），所有请求共用上下文 | Ruling 45 |
| 不改 service 签名 | HTTP 层只做参数校验 + 调 service，**不重写业务逻辑** | 本计划 |
| 错误映射 | `InkloomError.code` → HTTP 状态码（见 Task 1 的表） | spec §7 |
| 前端不写业务 | 所有状态由服务端算，前端只渲染 + 触发 | 本计划 |
| 状态管理 | Zustand 按域拆（`useSessionStore` 只管"当前章/选中场景"） | spec 引用架构 |
| 数据请求 | TanStack Query，**不手写 fetch 缓存** | spec 引用架构 |
| 样式 | Tailwind + shadcn/ui 的 Radix 原语，**不手搓下拉框/弹窗** | spec 引用架构 |
| 中文 diff | 复用 `@inkloom/core` 的 `diffText`（P1-b Task 1） | spec §4.7 |
| 端口 | API `8787`，Web `5173`（Vite 默认），Vite 代理 `/api` → 8787 | 本计划 |
| `exactOptionalPropertyTypes` | 可选字段赋值写 `...(x === undefined ? {} : { x })` | tsconfig |
| 测试 | HTTP 用 `*.http.test.ts`（supertest 风格，直接调 `app.request()`） | 本计划 |

### Ruling 45：HTTP 层用「单书模式」，不做多书并发

**决定**：服务启动时用 `INKLOOM_BOOK=<dir>` 指定一本书，`setContext` 在整个进程内只设一次。

**为什么不做多书**：
- 现在全部 12 个 service 函数都通过 `getContext()` 读全局单例。改成"每请求传 ctx"是一次波及所有文件的重构，而它的收益（同时开两本书）在单用户本地写作场景里接近零。
- spec 的 Stage 1 是"书架 → 建书 → 写作页"，但书架是 **P2-8**，不在 P1 范围。
- 真要做多书，正确做法是把 `getContext()` 换成 AsyncLocalStorage 或显式参数——那是 P2 的活。

**代价**：切换书要重启服务。**缓解**：`pnpm dev` 的脚本接受 `--book` 参数；前端顶部显示当前书名，让人不会搞错。

**如果这个决定错了**：所有 service 的 `getContext()` 调用点都要改成 `ctx` 参数——**机械替换，不需要重新设计**。这是可逆的。

- [ ] **Step 3: 实现 errors.ts**

```ts
import { InkloomError } from '@inkloom/shared'

export interface ApiError {
  error: { code: string; message: string }
}

/**
 * InkloomError.code → HTTP 状态码（spec §7）。
 *
 * ★ 未知码一律 500：静默降级成 400 会让「服务端 bug」看起来像「用户输入错」，
 *   排查时会被误导。
 */
export function httpStatusFor(code: string): 400 | 401 | 404 | 409 | 422 | 500 {
  switch (code) {
    case 'INVALID_INPUT':
    case 'VALIDATION':
      return 400
    case 'AUTH':
      return 401
    case 'NOT_FOUND':
      return 404
    case 'CONFLICT':
    case 'CAS_MISMATCH':
    case 'ALREADY_EXISTS':
      return 409
    case 'UNPROCESSABLE':
      return 422
    default:
      return 500
  }
}

export function toApiError(e: unknown): { status: number; body: ApiError } {
  if (e instanceof InkloomError) {
    return {
      status: httpStatusFor(e.code),
      body: { error: { code: e.code, message: e.message } },
    }
  }
  // ★ 只回 message，不带 stack：堆栈会泄漏绝对路径
  const message = e instanceof Error ? e.message : String(e)
  return { status: 500, body: { error: { code: 'INTERNAL', message } } }
}
```

- [ ] **Step 4: 实现 app.ts**

```ts
import { Hono } from 'hono'
import { cors } from 'hono/cors'
import { logger } from 'hono/logger'
import { HTTPException } from 'hono/http-exception'
import { toApiError } from './routes/errors.js'
import { actions } from './routes/actions.js'
import { read } from './routes/read.js'

export function createApp(): Hono {
  const app = new Hono()

  if (process.env['INKLOOM_HTTP_LOG'] === '1') app.use('*', logger())
  // 开发期前端在 5173，API 在 8787
  app.use('/api/*', cors({ origin: (o) => o ?? '*', credentials: false }))

  app.get('/api/health', (c) => c.json({ ok: true }))

  app.route('/api', read)
  app.route('/api', actions)

  app.notFound((c) => c.json({ error: { code: 'NOT_FOUND', message: '没有这个接口' } }, 404))

  app.onError((err, c) => {
    if (err instanceof HTTPException) {
      return c.json({ error: { code: 'HTTP', message: err.message } }, err.status)
    }
    const { status, body } = toApiError(err)
    // 5xx 打日志，4xx 不打（用户输入错不是服务端问题）
    if (status >= 500) console.error('[api]', err)
    return c.json(body, status as 400)
  })

  return app
}

export const app = createApp()
```

> ⚠️ `c.json(body, status)` 的第二个参数类型是 Hono 的 `StatusCode`。`toApiError` 返回 `number`
> 时用 `as 400` 绕不过类型检查——把 `toApiError` 的返回类型收窄为 Hono 支持的字面量联合
> （`400 | 401 | 404 | 409 | 422 | 500`），或在 `c.json` 前 `as never`。**选前者**（更安全）。

```ts
import { serve } from '@hono/node-server'
import { existsSync } from 'node:fs'
import { resolve } from 'node:path'
import { openBookIndexDb } from './index-db/open-book.js'
import { createApp } from './app.js'
import { setContext } from './services/context.js'
import { openProject } from './storage/project.js'

export async function startServer(opts: { bookDir: string; port?: number }): Promise<void> {
  const bookDir = resolve(opts.bookDir)
  if (!existsSync(bookDir)) {
    throw new Error(`书籍目录不存在：${bookDir}`)
  }
  // ★ 单书模式（Ruling 45）：启动时绑定，整个进程共用
  const opened = await openProject(bookDir)
  const db = await openBookIndexDb(bookDir)
  await setContext({ root: bookDir, db, project: opened.project })

  const port = opts.port ?? 8787
  serve({ fetch: createApp().fetch, port })
  console.log(`✓ inkloom API  http://localhost:${port}`)
  console.log(`  书          ${opened.project.name}（${bookDir}）`)
}

// 直接用 `pnpm api` 启动时才跑（被 import 时不跑）
if (process.argv[1]?.endsWith('server.ts') === true) {
  const book = process.env['INKLOOM_BOOK']
  if (book === undefined) {
    console.error('缺少 INKLOOM_BOOK=<书籍目录>，例如：INKLOOM_BOOK=fixtures/qixia pnpm api')
    process.exit(1)
  }
  await startServer({ bookDir: book, port: Number(process.env['PORT'] ?? 8787) })
}
```

```ts
import { diffText, summarizeDiff } from '@inkloom/core'
import { InkloomError, blueprintSchema } from '@inkloom/shared'
import { Hono } from 'hono'
import { getContext } from '../services/context.js'
import { listChapterScenes } from '../services/scene-review-service.js'
import { readJsonArray } from '../storage/elements.js'
import { listSceneVersions, readSceneFile } from '../storage/scenes.js'

export const read = new Hono()

/** 解析并校验路径参数，非法时抛 INVALID_INPUT（由 app.onError 转 400） */
function intParam(raw: string | undefined, name: string): number {
  const n = Number(raw)
  if (!Number.isInteger(n) || n <= 0) {
    throw new InkloomError('INVALID_INPUT', `${name} 必须是正整数，收到 ${String(raw)}`)
  }
  return n
}

read.get('/book', async (c) => {
  const { project, db } = getContext()
  const chapters = await db.chapter.findMany({
    where: { projectId: project.id },
    orderBy: { chapterNo: 'asc' },
    select: {
      chapterNo: true,
      title: true,
      status: true,
      wordCount: true,
      summary: true,
      finalizedAt: true,
    },
  })
  return c.json({ ...project, chapters })
})

read.get('/chapters/:n', async (c) => {
  const chapterNo = intParam(c.req.param('n'), 'chapterNo')
  const { db, project } = getContext()
  const [chapter, scenes] = await Promise.all([
    db.chapter.findUnique({
      where: { projectId_chapterNo: { projectId: project.id, chapterNo } },
    }),
    listChapterScenes(chapterNo),
  ])
  return c.json({
    chapterNo,
    title: chapter?.title ?? null,
    status: chapter?.status ?? 'planned',
    wordCount: chapter?.wordCount ?? 0,
    summary: chapter?.summary ?? null,
    scenes,
  })
})

  const sceneNo = intParam(c.req.param('sceneNo'), 'sceneNo')
  const { root } = getContext()
  const versionRaw = c.req.query('version')
  const version =
    versionRaw === undefined
      ? Math.max(...(await listSceneVersions(root, chapterNo, sceneNo)), 0)
      : intParam(versionRaw, 'version')
  if (version === 0) throw new InkloomError('NOT_FOUND', `第 ${chapterNo} 章场景 ${sceneNo} 没有版本`)
  const scene = await readSceneFile(root, chapterNo, sceneNo, version)
  if (scene === null) {
    throw new InkloomError('NOT_FOUND', `第 ${chapterNo} 章场景 ${sceneNo} v${version} 不存在`)
  }
  return c.json({ sceneNo, version, segments: scene.segments })
})

    a.segments.map((s) => s.text).join('\n\n'),
    b.segments.map((s) => s.text).join('\n\n'),
  )
  return c.json({ ...summarizeDiff(spans), spans })
})

read.get('/blueprints', async (c) => {
```

```ts
export class ApiError extends Error {
  constructor(
    readonly code: string,
    message: string,
    readonly status: number,
  ) {
    super(message)
    this.name = 'ApiError'
  }
}

/**
 * 统一的 fetch 封装。
 *
 * ★ 错误必须抛 ApiError（带 code）：UI 要按 code 分支
 *   （AUTH → 提示填 key；CONFLICT → 提示刷新）。
 */
export async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`/api${path}`, {
    ...init,
    headers: {
      ...(init?.body === undefined ? {} : { 'content-type': 'application/json' }),
      ...(init?.headers ?? {}),
    },
  })
  const text = await res.text()
  const json: unknown = text.length === 0 ? null : JSON.parse(text)
  if (!res.ok) {
    const e = json as { error?: { code?: string; message?: string } } | null
    throw new ApiError(e?.error?.code ?? 'UNKNOWN', e?.error?.message ?? res.statusText, res.status)
  }
  return json as T
}
```

## 附录 B：本计划的已知缺口

| # | 缺口 | 影响 | 补法 |
|---|---|---|---|
| 1 | 生成是阻塞请求（40–90 秒） | 浏览器转圈，可能超时 | 改 SSE 或"提交任务 + 轮询 runId" |
| 2 | 无鉴权 | 本机用无所谓；暴露到局域网就危险 | 绑定 `127.0.0.1` + 启动时打印警告 |
| 3 | 单书模式 | 切书要重启 | AsyncLocalStorage 或显式 ctx（P2） |
| 4 | 无前端自动化测试 | UI 回归靠手工 | Playwright（P2-5 键盘流一起做） |
| 5 | 字数 75–85% | 界面不会提示"写短了" | Toolbar 加字数对比提示 |
