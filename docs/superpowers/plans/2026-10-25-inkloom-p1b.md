# inkloom P1-b 实现计划（确认与定稿）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让生成的候选稿能被逐场景接受、拒绝、编辑，并在全部确认后定稿成一章正文——从而完成"生成 → 审阅 → 定稿"的完整单章闭环。

**Architecture:** 三层分工不变：`core/diff` 是纯函数（字符级 diff，spec §4.7），`api/services` 负责编排（审阅、定稿、状态提案），`cli` 是唯一入口。**落库以用户接受哪个版本为准**，diff 只做展示。

**Tech Stack:** 现有栈 + `diff@9`（jsdiff，spec §4.7 指定的 `diffChars`）。

**Spec:** `docs/superpowers/specs/2026-10-25-inkloom-design.md` §4.1 第 8–9 步（逐场景操作与定稿）、§4.7（diff 规则）、§4.8（状态推导）、§3.9（DraftSegment）、ADR-27（正文不进 revision）

## Global Constraints

| 约束 | 值 / 规则 | 出处 |
|---|---|---|
| accept 的副作用 | `DraftSegment.status = 'accepted'` + 原子写场景文件 + `git commit`；**不写 EntityRevision** | §4.1 [8]、ADR-27 |
| reject 的副作用 | 只改 `status = 'rejected'`，**不删文件**（保留作对照） | §4.1 [8] |
| accepted 互斥 | 同章同场景**同一时刻只能有一个 accepted 版本**；接受新版本时旧版本自动降为 rejected | 本计划 Ruling 36 |
| diff 粒度 | **字符级**（`diffChars`），行级对中文无意义 | §4.7 |
| diff 的作用 | **只展示，不参与落库决策** | §4.7 |
| 定稿前置 | 该章**不得有 `candidate` 状态的段** | §4.1 [9] |
| 定稿副作用 | 合并场景 → `chapters/ch-NNN.md`（原子写）+ `Chapter.status='finalized'` + `finalizedAt` + `wordCount` + `git commit` | §4.1 [9] |
| 撤销定稿 | `finalized → review`，正文文件保留 | §3.x 状态机 |
| `stateChapter` 语义 | 「从第几章起生效」；定稿第 N 章后的变化记 **N+1** | §4.8 |
| 状态提案 | LLM 只**提案**，用户逐条确认后才写 revision；未确认的角色标 `stateStale` | §4.1 [9]、§5 |
| 摘要（C3） | 定稿时生成约 200 字摘要，写 `Chapter.summary` + `summaryHash`，`summaryStale=false` | §4.4 |
| `prompt` / `core` 零 IO | 仍然由 `scripts/check-deps.mjs` 强制 | §2.1 |
| `exactOptionalPropertyTypes` | 可选字段赋值写 `...(x === undefined ? {} : { x })` | tsconfig |
| 测试 | 纯函数 `*.test.ts`（unit）；涉 IO `*.int.test.ts`（integration） | 约定 |

### 明确不做（P1-b 的 YAGNI 清单）

| 不做 | 为什么 |
|---|---|
| UI | P1-c |
| HTTP 路由 | 单用户本地工具，CLI 足够（Ruling 21 继续生效） |
| 多章批量操作 | 一次一章，避免"批量毁掉 10 章" |
| 自动接受（无人工确认） | 违反 §5「AI 只提案」 |
| `QualityReview` 打分 | spec 标为"可选"，且需要另一套评分 prompt，v1 不做 |
| 撤销单段编辑 | `edit` 生成新版本，旧版本仍在（天生可回退），不需要专门的 undo |
| 生成时自动续写补字数 | 见 P1-a 附录 B；这是"生成"侧的事，不是"确认"侧 |

### Ruling 36：accepted 互斥

**决定**：同章同场景，接受一个版本时把其他 `accepted` 版本自动降级为 `rejected`。

**为什么**：spec §4.1 [8] 只说"accept → status=accepted"，没说多个版本能否同时 accepted。若允许多个，`finalize` 时无法确定用哪个版本合并——而 `Chapter` 只有一个正文文件。数据库层也不适合加唯一约束（partial unique index 在 SQLite+Prisma 里表达不了）。

**代价**：用户不能"暂时接受两个版本，定稿时再选"。但 P1-b 的交互是"逐场景确认"，这个限制符合使用方式。

```ts
import { diffChars } from 'diff'

export type DiffOp = 'same' | 'add' | 'remove'

export interface DiffSpan {
  op: DiffOp
  text: string
}

export interface DiffSummary {
  addedChars: number
  removedChars: number
  unchangedChars: number
  /** 相似度 0–1：unchanged / max(lenA, lenB)；两边都空时为 1 */
  similarity: number
}

/**
 * 字符级 diff（spec §4.7）。
 *
 * ★ 为什么不用行级：中文没有空格分词，一行可能就是一整段，
 *   行级 diff 会把"改了一个字"显示成"整段替换"，用户无法审阅。
 * ★ 为什么不用词级：中文没有天然词边界，分词器会引入歧义和新依赖。
 */
export function diffText(oldText: string, newText: string): DiffSpan[] {
  return diffChars(oldText, newText).map((part) => ({
    op: part.added === true ? 'add' : part.removed === true ? 'remove' : 'same',
    text: part.value,
  }))
}

export function summarizeDiff(spans: DiffSpan[]): DiffSummary {
  let addedChars = 0
  let removedChars = 0
  let unchangedChars = 0
  for (const s of spans) {
    const n = s.text.length
    if (s.op === 'add') addedChars += n
    else if (s.op === 'remove') removedChars += n
    else unchangedChars += n
  }
  const oldLen = unchangedChars + removedChars
  const newLen = unchangedChars + addedChars
  const denom = Math.max(oldLen, newLen)
  return {
    addedChars,
    removedChars,
    unchangedChars,
    // 两边都空视为完全一致（避免 0/0 = NaN 污染下游比较）
    similarity: denom === 0 ? 1 : unchangedChars / denom,
  }
}

const HINT_PREVIEW_CHARS = 40

/**
 * 生成终端可读的变更提示。
 *
 * ★ 只列 add / remove：same 在审阅场景里是噪音
 *   （一段 500 字的文本改了 3 个字，列出全部 same 会让 3 处变更淹没在 500 字里）。
 */
export function renderDiffHints(spans: DiffSpan[], maxHints = 10): string[] {
  const changed = spans.filter((s) => s.op !== 'same' && s.text.length > 0)
  const hints: string[] = []
  for (const s of changed.slice(0, maxHints)) {
    const marker = s.op === 'add' ? '+' : '-'
    const preview =
      s.text.length > HINT_PREVIEW_CHARS ? `${s.text.slice(0, HINT_PREVIEW_CHARS)}…` : s.text
    // 换行在终端里显示成 ⏎，否则一条提示会被拆成多行
    hints.push(`${marker} ${preview.replace(/\n/g, '⏎')}`)
  }
  if (changed.length > maxHints) {
    hints.push(`… 还有 ${changed.length - maxHints} 处变更`)
  }
  return hints
}
```

```ts
import { hashContent } from '../storage/atomic-write.js'
import { commitAll, initRepo } from '../git/runner.js'
import { readSceneFile, writeSceneFile } from '../storage/scenes.js'
import { countWords } from '@inkloom/core'
import { InkloomError } from '@inkloom/shared'
import { getContext } from './context.js'

export interface SceneRow {
  sceneNo: number
  version: number
  relPath: string
  wordCount: number
  segCount: number
  status: 'candidate' | 'accepted' | 'rejected'
  acceptedAt: Date | null
}

export interface AcceptSceneInput {
  chapterNo: number
  sceneNo: number
  version: number
}

export interface EditSceneSegInput extends AcceptSceneInput {
  segId: string
  newText: string
}

/** 状态保守度：有 candidate 就算 candidate，否则有 rejected 算 rejected，全 accepted 才 accepted */
function aggregateStatus(statuses: string[]): SceneRow['status'] {
  if (statuses.includes('candidate')) return 'candidate'
  if (statuses.includes('rejected')) return 'rejected'
  return 'accepted'
}

/** 列出某章所有场景版本（按 sceneNo → version 升序） */
export async function listChapterScenes(chapterNo: number): Promise<SceneRow[]> {
  const { db, project } = getContext()
  const segs = await db.draftSegment.findMany({
    where: { projectId: project.id, chapterNo, deletedAt: null },
    orderBy: [{ sceneNo: 'asc' }, { seq: 'asc' }],
  })
  const byKey = new Map<string, typeof segs>()
  for (const s of segs) {
    // filePath 形如 chapters/ch-004/scenes/s1.v1.md，版本号只能从路径解析
    const key = `${s.sceneNo}__${s.filePath}`
    const list = byKey.get(key) ?? []
    list.push(s)
    byKey.set(key, list)
  }
  const rows: SceneRow[] = []
  for (const list of byKey.values()) {
    const first = list[0]
    if (first === undefined) continue
    const version = Number(/\.v(\d+)\.md$/.exec(first.filePath)?.[1] ?? '0')
    rows.push({
      sceneNo: first.sceneNo,
      version,
      relPath: first.filePath,
      segCount: list.length,
      wordCount: list.reduce((n, s) => n + (s.wordCount ?? 0), 0),
      status: aggregateStatus(list.map((s) => s.status)),
      acceptedAt: list.find((s) => s.acceptedAt !== null)?.acceptedAt ?? null,
    })
  }
  return rows.sort((a, b) => a.sceneNo - b.sceneNo || a.version - b.version)
}

async function assertVersionExists(input: AcceptSceneInput): Promise<{ relPath: string; segIds: string[] }> {
  const { db, project } = getContext()
  const rows = await db.draftSegment.findMany({
    where: { projectId: project.id, chapterNo: input.chapterNo, sceneNo: input.sceneNo },
    select: { filePath: true, segId: true },
  })
  const matched = rows.filter((r) => {
    const v = Number(/\.v(\d+)\.md$/.exec(r.filePath)?.[1] ?? '0')
    return v === input.version
  })
  const relPath = matched[0]?.filePath
  if (relPath === undefined) {
    throw new InkloomError(
      'NOT_FOUND',
      `第 ${input.chapterNo} 章场景 ${input.sceneNo} 没有 v${input.version}`,
    )
  }
  return { relPath, segIds: matched.map((r) => r.segId) }
}

/**
 * 接受某个场景版本。
 *
 * ★ 同场景其他 accepted 版本自动降为 rejected（Ruling 36）：
 *   finalize 只能把"一个版本"合并进正文文件，允许多个 accepted 会让定稿产生歧义。
 * ★ 不写 EntityRevision：正文历史归 Git（ADR-27）。
 */
export async function acceptScene(input: AcceptSceneInput): Promise<{ relPath: string }> {
  const { root, db, project } = getContext()
  const { relPath } = await assertVersionExists(input)
  const now = new Date()

  await writeQueueGuard(async () => {
    // 1. 同章同场景、不是本版本 → 全部 rejected
    await db.draftSegment.updateMany({
      where: {
        projectId: project.id,
        chapterNo: input.chapterNo,
        sceneNo: input.sceneNo,
        filePath: { not: relPath },
        status: 'accepted',
      },
      data: { status: 'rejected' },
    })
    // 2. 本版本 → accepted
    await db.draftSegment.updateMany({
      where: { projectId: project.id, chapterNo: input.chapterNo, sceneNo: input.sceneNo, filePath: relPath },
      data: { status: 'accepted', acceptedAt: now },
    })
    await initRepo(root)
    await commitAll(root, `feat(scene): 接受第 ${input.chapterNo} 章场景 ${input.sceneNo} v${input.version}`)
  })
  return { relPath }
}

/** 拒绝某个版本：只改状态，不删文件（保留作对照） */
export async function rejectScene(input: AcceptSceneInput): Promise<void> {
  const { root, db, project } = getContext()
  const { relPath } = await assertVersionExists(input)
  await db.draftSegment.updateMany({
    where: { projectId: project.id, chapterNo: input.chapterNo, sceneNo: input.sceneNo, filePath: relPath },
    data: { status: 'rejected' },
  })
  await initRepo(root)
  await commitAll(root, `chore(scene): 拒绝第 ${input.chapterNo} 章场景 ${input.sceneNo} v${input.version}`)
}

/**
 * 编辑某版本里的一段，产出新版本。
 *
 * ★ segId 保持不变：段身份是 segId（全书唯一、永不复用），不是位置。
 *   如果换新的 segId，之前的单段回退记录就找不到这个段了。
 * ★ 旧版本整版标 rejected：编辑等于"基于 vN 改出一版"，vN 不再是候选。
 */
export async function editSceneSeg(input: EditSceneSegInput): Promise<{ newVersion: number; relPath: string }> {
  const { root, db, project } = getContext()
  const text = input.newText.trim()
  if (text.length === 0) {
    throw new InkloomError('INVALID_INPUT', '段文本不能为空（不允许把段改空，请改用 reject）')
  }

  const { relPath } = await assertVersionExists(input)
  // ❗readSceneFile 的签名是 (root, chapterNo, sceneNo, version)，不是 relPath
  const scene = await readSceneFile(root, input.chapterNo, input.sceneNo, input.version)
  if (scene === null) {
    throw new InkloomError(
      'NOT_FOUND',
      `第 ${input.chapterNo} 章场景 ${input.sceneNo} v${input.version} 的文件不存在`,
    )
  }
  const idx = scene.segments.findIndex((s) => s.segId === input.segId)
  if (idx < 0) {
    throw new InkloomError('NOT_FOUND', `${relPath} 里没有段 ${input.segId}`)
  }

  const nextSegments = scene.segments.map((s, i) => (i === idx ? { segId: s.segId, text } : s))
  const newVersion = scene.version + 1
  const written = await writeSceneFile(
    root,
    { sceneNo: input.sceneNo, version: newVersion, segments: nextSegments },
    input.chapterNo,
  )

  await db.$transaction(async (tx) => {
    // 旧版本整版标 rejected
    await tx.draftSegment.updateMany({
      where: { projectId: project.id, chapterNo: input.chapterNo, sceneNo: input.sceneNo, filePath: relPath },
      data: { status: 'rejected' },
    })
    // 新版本全部 candidate
    await tx.draftSegment.createMany({
      data: nextSegments.map((s, seq) => ({
        id: `seg_${input.chapterNo}_${input.sceneNo}_${newVersion}_${s.segId}`,
        projectId: project.id,
        chapterNo: input.chapterNo,
        sceneNo: input.sceneNo,
        segId: s.segId,
        seq,
        filePath: written.relPath,
        contentHash: hashContent(s.text),
        wordCount: countWords(s.text),
        status: 'candidate',
      })),
    })
  })

  await initRepo(root)
  await commitAll(root, `feat(scene): 编辑第 ${input.chapterNo} 章场景 ${input.sceneNo} 段 ${input.segId} → v${newVersion}`)
  return { newVersion, relPath: written.relPath }
}

/** 写队列守卫：本模块不需要全局队列（单用户 CLI），保留占位以便未来接 Hono 时统一加锁 */
async function writeQueueGuard<T>(fn: () => Promise<T>): Promise<T> {
  return fn()
}
```

### Ruling 37：摘要用蓝图拼装，不调 LLM

**决定**：`buildSummaryFromBlueprint` 把 `goal / conflict / turn / hook` 拼成摘要，不调 LLM。

**依据**：spec §4.4 的表格写"每章 200 字，LLM 生成"，但同一节下方的**核心决策**明确否定了它：

> 「Pagekin 的 `global_summary` 定义为"章节要点时间线（**从蓝图按序拼装**）"，而非 LLM 总结。20 章后你不需要 20 段摘要，你需要 20 条蓝图要点。」

表格是早期设计，被正文的决策覆盖。取正文。

**代价**：摘要只有约 50–80 字，不是 200 字。但 U4 块的作用是"提醒前面发生了什么"，蓝图要点比 LLM 概括更准（不会漏、不会编）。**省钱且更可查**。

```ts
import { createHash } from 'node:crypto'
import type { Blueprint } from '@inkloom/shared'
import { getContext } from '../services/context.js'

/**
 * 从蓝图四要素拼装 C3 层摘要（Ruling 37）。
 *
 * ★ 为什么不用 LLM 概括：spec §4.4 的核心决策是"用结构化数据替代文本摘要"。
 *   LLM 概括会漏要点、会编情节，而蓝图是作者自己写的，逐字可靠。
 */
export function buildSummaryFromBlueprint(bp: Blueprint): string {
  const parts: string[] = []
  parts.push(bp.goal)
  parts.push(`冲突：${bp.conflict}`)
  if (bp.turn !== undefined) parts.push(`转折：${bp.turn}`)
  parts.push(`钩子：${bp.hook}`)
  return parts.join('；')
}

/** 写 Chapter.summary。summaryHash 用于判断"正文改了但摘要没更新" */
export async function upsertChapterSummary(chapterNo: number, summary: string): Promise<void> {
  const { db, project } = getContext()
  const summaryHash = createHash('sha256').update(summary).digest('hex').slice(0, 16)
  await db.chapter.upsert({
    where: { projectId_chapterNo: { projectId: project.id, chapterNo } },
    create: {
      id: `ch_${project.id}_${chapterNo}`,
      projectId: project.id,
      chapterNo,
      status: 'drafting',
      summary,
      summaryHash,
      summaryStale: false,
    },
    update: { summary, summaryHash, summaryStale: false },
  })
}
```

```ts
import { countWords } from '@inkloom/core'
import { InkloomError, blueprintSchema } from '@inkloom/shared'
import { commitAll, initRepo } from '../git/runner.js'
import { mergeChapter } from '../storage/chapters.js'
import { readJsonElement } from '../storage/elements.js'
import { readSceneFile } from '../storage/scenes.js'
import { buildSummaryFromBlueprint, upsertChapterSummary } from '../storage/summaries.js'
import { getContext } from './context.js'

export interface FinalizeResult {
  relPath: string
  wordCount: number
  sceneCount: number
  summary: string
}

/**
 * 定稿（spec §4.1 [9]）。
 *
 * 顺序：
 *   1 校验：该章不得有 candidate（逐场景确认是定稿的前提）
 *   2 取每个场景的 accepted 版本
 *   3 合并 → chapters/ch-NNN.md（保留 <!-- scene:N --> 供撤销时反解）
 *   4 Chapter.status = finalized
 *   5 摘要（Ruling 37：蓝图拼装）
 *   6 git commit
 *
 * ★ 幂等：重复定稿会重新合并同一批 accepted 场景，结果一致。
 */
export async function finalizeChapter(input: { chapterNo: number; title?: string }): Promise<FinalizeResult> {
  const { root, db, project } = getContext()

  // 1. 校验
  const candidates = await db.draftSegment.count({
    where: { projectId: project.id, chapterNo: input.chapterNo, status: 'candidate', deletedAt: null },
  })
  if (candidates > 0) {
    throw new InkloomError(
      'INVALID_INPUT',
      `第 ${input.chapterNo} 章还有 ${candidates} 个段处于 candidate（未确认），不能定稿`,
    )
  }

  // 2. 取 accepted 版本（同场景理论上只有一个，Ruling 36 保证）
  const accepted = await db.draftSegment.findMany({
    where: { projectId: project.id, chapterNo: input.chapterNo, status: 'accepted', deletedAt: null },
    orderBy: [{ sceneNo: 'asc' }, { seq: 'asc' }],
  })
  if (accepted.length === 0) {
    throw new InkloomError('INVALID_INPUT', `第 ${input.chapterNo} 章没有已接受的场景，不能定稿`)
  }

  const sceneNos = [...new Set(accepted.map((s) => s.sceneNo))]
  const scenes: { sceneNo: number; text: string }[] = []
  for (const sceneNo of sceneNos) {
    const first = accepted.find((s) => s.sceneNo === sceneNo)
    if (first === undefined) continue
    const version = Number(/\.v(\d+)\.md$/.exec(first.filePath)?.[1] ?? '0')
    const scene = await readSceneFile(root, input.chapterNo, sceneNo, version)
    if (scene === null) {
      throw new InkloomError('NOT_FOUND', `场景文件缺失：${first.filePath}`)
    }
    scenes.push({
      sceneNo,
      text: scene.segments.map((s) => s.text).join('\n\n'),
    })
  }

  // 3. 合并正文
  const bpRaw = await readJsonElement(
    root,
    `story/blueprints/ch-${String(input.chapterNo).padStart(3, '0')}.json`,
  )
  const bp = bpRaw === null ? null : blueprintSchema.safeParse(bpRaw)
  const blueprint = bp !== null && bp.success ? bp.data : null
  const title = input.title ?? blueprint?.title ?? `第 ${input.chapterNo} 章`
  const merged = await mergeChapter(root, { chapterNo: input.chapterNo, title, scenes })
  const body = scenes.map((s) => s.text).join('')
  const wordCount = countWords(body)

  // 4. Chapter 状态
  await db.chapter.upsert({
    where: { projectId_chapterNo: { projectId: project.id, chapterNo: input.chapterNo } },
    create: {
      id: `ch_${project.id}_${input.chapterNo}`,
      projectId: project.id,
      chapterNo: input.chapterNo,
      title,
      status: 'finalized',
      wordCount,
      finalizedAt: new Date(),
    },
    update: { title, status: 'finalized', wordCount, finalizedAt: new Date() },
  })

  // 5. 摘要（零 LLM）
  const summary = blueprint === null ? '' : buildSummaryFromBlueprint(blueprint)
  if (summary.length > 0) await upsertChapterSummary(input.chapterNo, summary)

  // 6. commit
  await initRepo(root)
  await commitAll(root, `feat(chapter): 定稿第 ${input.chapterNo} 章（${scenes.length} 场景 / ${wordCount} 字）`)

  return { relPath: merged.relPath, wordCount, sceneCount: scenes.length, summary }
}

/**
 * 撤销定稿：finalized → review。
 *
 * ★ 不删正文文件：撤销只是"允许再改"，已定稿的文字仍是唯一真相。
 */
export async function unfinalizeChapter(input: { chapterNo: number }): Promise<void> {
  const { root, db, project } = getContext()
  const ch = await db.chapter.findUnique({
    where: { projectId_chapterNo: { projectId: project.id, chapterNo: input.chapterNo } },
  })
  if (ch === null || ch.status !== 'finalized') {
    throw new InkloomError(
      'INVALID_INPUT',
      `第 ${input.chapterNo} 章当前状态是 ${ch?.status ?? '不存在'}，只有 finalized 才能撤销`,
    )
  }
  await db.chapter.update({
    where: { id: ch.id },
    data: { status: 'review', finalizedAt: null },
  })
  await initRepo(root)
  await commitAll(root, `chore(chapter): 撤销定稿第 ${input.chapterNo} 章`)
}
```

### Ruling 38：提案用行格式，不用 JSON

**决定**：让模型输出 `角色ID|字段|新值|证据原文`，每行一条。

**依据**：spec §4.6 的"不用 JSON"是针对**正文生成**（JSON 转义破坏语感）。这里虽然是结构化数据，但"证据原文"是**中文原文引用**——塞进 JSON 字符串一样要转义引号和换行，模型容易写坏。

行格式的额外好处：解析失败时能单独跳过某一行（`unparsed`），而 JSON 解析失败就整体报废。

**代价**：`|` 不能出现在证据原文里。缓解：解析时按**前 3 个** `|` 切分，剩下的全归证据（证据里即使有 `|` 也不影响）。

> ★ **payload 结构铁律**：`RevisionRecord.payload` 是 `string`，内容是**扁平实体快照**（`{ id, name, curPhysical, stateChapter, stateStale, ... }`），**不是** `{ state: {...} }` 嵌套。
> 依据：`resolveCharacterState` 返回 `{ state }` 时 `state` 就是 `JSON.parse(payload)` 本身，`context-loader` 据此读 `snap.state['curPhysical']`。嵌一层会让装配层读不到状态。
> ★ 必须用 `nextRevision()` 构造（它负责 `version` 递增、`parentRevisionId` 串链、`payload` 序列化校验），不要手写字段。

```ts
export type ProposalField = 'curPhysical' | 'curMental' | 'curTierId'
const ALLOWED_FIELDS: readonly ProposalField[] = ['curPhysical', 'curMental', 'curTierId']

export interface StateProposal {
  id: string
  characterId: string
  characterName: string
  field: ProposalField
  newValue: string
  evidenceQuote: string
  stateChapter: number
}

export interface ProposeResult {
  runId: string
  proposals: StateProposal[]
  unparsed: string[]
}

function newRunId(): string {
  return `run_${randomUUID().replace(/-/g, '').slice(0, 16)}`
}

const SYSTEM_PROMPT = `你是小说编辑助手。你的任务是读一章正文，找出"角色状态发生了变化"的地方。

只关注三个字段：
- curPhysical：身体状态（受伤、中毒、断臂、失明…）
- curMental：心理状态（恐惧、决意、崩溃、释然…）
- curTierId：修为境界（仅当正文明确写出突破/跌落时）

输出格式：每行一条，用竖线分隔，**不要任何其它文字**：
角色ID|字段|新值|证据原文
- 新值：不超过 12 字的短语
- 证据原文：从正文里逐字复制的一句，不超过 40 字
- 没有变化就不输出任何行`

async function readChapterBody(root: string, chapterNo: number): Promise<string> {
  const name = `ch-${String(chapterNo).padStart(3, '0')}.md`
  const raw = await readIfExists(join(bookPaths(root).chapters, name))
  if (raw === null) {
    throw new InkloomError('NOT_FOUND', `第 ${chapterNo} 章没有定稿正文，无法做状态提案`)
  }
  // 去掉标题行与场景标记，只留正文
  return raw
    .replace(/^#.*$/m, '')
    .replace(/<!--[\s\S]*?-->/g, '')
    .trim()
}

/**
 * 调 LLM 产出状态变更提案（spec §4.1 [9]）。
 *
 * ★ 只提案，不落库：写入 revision 必须用户逐条确认（§5「AI 只提案」）。
 * ★ stateChapter = 本章 + 1：spec §4.8——第 N 章结尾的断臂不能喂给第 N 章开头。
 */
export async function proposeStateChanges(input: {
  chapterNo: number
  apiKey: string
  fetchImpl?: FetchLike
  model?: string
}): Promise<ProposeResult> {
  const { root, db, project } = getContext()
  const body = await readChapterBody(root, input.chapterNo)

  const rawChars = await readJsonArray(root, 'characters/index.json')
  const cast: { id: string; name: string }[] = []
  for (const item of rawChars) {
    const r = characterSchema.safeParse(item)
    if (r.success) cast.push({ id: r.data.id, name: r.data.name })
  }

  const runId = newRunId()
  const model = input.model ?? 'deepseek-flash'
  await db.generationRun.create({
    data: {
      id: runId,
      projectId: project.id,
      chapterNo: input.chapterNo,
      commitState: 'pending',
      purpose: 'state_proposal',
      provider: 'deepseek',
      model,
      assembledPrompt: JSON.stringify([
        { role: 'system', content: SYSTEM_PROMPT },
        { role: 'user', content: '' },
      ]),
      status: 'running',
    },
  })

  const userPrompt = [
    '【角色列表】',
    ...cast.map((c) => `${c.id} = ${c.name}`),
    '',
    '【本章正文】',
    body,
  ].join('\n')

  let content: string
  try {
    const r = await chat({
      apiKey: input.apiKey,
      model,
      messages: [
        { role: 'system', content: SYSTEM_PROMPT },
        { role: 'user', content: userPrompt },
      ],
      maxTokens: 4000,
      ...(input.fetchImpl === undefined ? {} : { fetchImpl: input.fetchImpl }),
    })
    content = r.content
  } catch (e) {
    await db.generationRun.update({
      where: { id: runId },
      data: { status: 'failed', errorMessage: (e as Error).message, finishedAt: new Date() },
    })
    throw e
  }

  const proposals: StateProposal[] = []
  const unparsed: string[] = []
  for (const line of content.split('\n')) {
    const trimmed = line.trim()
    if (trimmed.length === 0) continue
    // ★ 只按前 3 个 | 切分：证据原文里可能含 |（Ruling 38）
    const parts = trimmed.split('|')
    if (parts.length < 4) {
      unparsed.push(trimmed)
      continue
    }
    const [charId, field, newValue, ...rest] = parts
    const evidence = rest.join('|').trim()
    const known = cast.find((c) => c.id === charId?.trim())
    if (known === undefined || !ALLOWED_FIELDS.includes(field?.trim() as ProposalField)) {
      unparsed.push(trimmed)
      continue
    }
    proposals.push({
      id: `prop_${proposals.length}_${charId?.trim()}`,
      characterId: known.id,
      characterName: known.name,
      field: field?.trim() as ProposalField,
      newValue: (newValue ?? '').trim(),
      evidenceQuote: evidence,
      stateChapter: input.chapterNo + 1,
    })
  }

  await db.generationRun.update({
    where: { id: runId },
    data: {
      status: 'success',
      output: JSON.stringify({ proposals, unparsed }),
      finishedAt: new Date(),
    },
  })

  return { runId, proposals, unparsed }
}

/** 取某章最近一次提案（apply 需要用它还原完整信息） */
export async function loadLatestProposals(chapterNo: number): Promise<StateProposal[]> {
  const { db, project } = getContext()
  const run = await db.generationRun.findFirst({
    where: { projectId: project.id, chapterNo, purpose: 'state_proposal', status: 'success' },
    orderBy: { startedAt: 'desc' },
  })
  if (run === null || run.output === null) {
    throw new InkloomError('NOT_FOUND', `第 ${chapterNo} 章还没有状态提案，先跑 propose`)
  }
  const parsed = JSON.parse(run.output) as { proposals: StateProposal[] }
  return parsed.proposals
}

/**
 * 应用用户确认的提案。
 *
 * ★ 逐条确认：只写 acceptIds 里的，其余跳过（§5「AI 只提案，人决定」）。
 * ★ 每个字段单独一条 revision：append-only，按字段落，便于后续按字段回退。
 */
export async function applyStateProposals(input: {
  chapterNo: number
  acceptIds: string[]
}): Promise<{ applied: number; skipped: number }> {
  const { root, db, project } = getContext()
  const proposals = await loadLatestProposals(input.chapterNo)
  const accepted = new Set(input.acceptIds)

  let applied = 0
  let skipped = 0
  const touched = new Set<string>()
  for (const p of proposals) {
    if (!accepted.has(p.id)) {
      skipped++
      continue
    }
    const prev = await lastRevision(root, 'character', p.characterId)
    // ★ payload 是「整个实体」的扁平快照，不是 { state: {...} } 嵌套：
    //   resolveCharacterState 返回的 state 就是 parsePayload(prev) 本身。
    const prevPayload: Record<string, unknown> =
      prev === null ? {} : (JSON.parse(prev.payload) as Record<string, unknown>)
    const revision = nextRevision({
      id: `rev_${p.characterId}_${(prev?.version ?? 0) + 1}`,
      entityType: 'character',
      entityId: p.characterId,
      prev,
      payload: {
        ...prevPayload,
        [p.field]: p.newValue,
        // stateChapter 语义：从第几章起生效（定稿第 N 章 → N+1）
        stateChapter: p.stateChapter,
        stateStale: false,
        sourceQuote: p.evidenceQuote,
        sourceChapter: input.chapterNo,
      },
      changeSource: 'ai',
      changeReason: `第 ${input.chapterNo} 章定稿：${p.field}`,
      now: new Date().toISOString(),
    })
    await appendRevision(root, revision)
    applied++
    touched.add(p.characterId)
  }

  // 清掉被提案角色的 stateStale（文件 + 索引）
  if (touched.size > 0) {
    const rawChars = await readJsonArray(root, 'characters/index.json')
    const next = rawChars.map((item) => {
      const r = characterSchema.safeParse(item)
      if (!r.success) return item
      if (!touched.has(r.data.id)) return item
      return { ...r.data, stateStale: false }
    })
    await writeJsonElement(root, 'characters/index.json', next)
    for (const id of touched) {
      await db.character.updateMany({
        where: { projectId: project.id, id },
        data: { stateStale: false },
      })
    }
  }

  return { applied, skipped }
}
```

> ⚠️ `RevisionRecord` 的字段名（`id` / `createdAt` / `payload`）以 `packages/core/src/revision/types.ts` 为准。若实际是 `recordedAt` 或 `ts`，按实际改——**不要为了迁就计划改类型**。
> ⚠️ `join` 需要从 `node:path` 导入。

```ts
export async function diffScene({ positional, flags }: CommandCtx): Promise<void> {
  const dir = requirePositional(
    positional,
    0,
    'inkloom diff <dir> --chapter N --scene M --from V1 --to V2',
  )
  const chapterNo = Number(requireFlag(flags, 'chapter'))
  const sceneNo = Number(requireFlag(flags, 'scene'))
  const from = Number(requireFlag(flags, 'from'))
  const to = Number(requireFlag(flags, 'to'))

  await withBook(dir, async () => {
    const { root } = getContext()
    const a = await readSceneFile(root, chapterNo, sceneNo, from)
    const b = await readSceneFile(root, chapterNo, sceneNo, to)
    if (a === null || b === null) {
      throw new Error(`场景 ${sceneNo} 的 v${a === null ? from : to} 不存在`)
    }
    const oldText = a.segments.map((s) => s.text).join('\n\n')
    const newText = b.segments.map((s) => s.text).join('\n\n')
    const spans = diffText(oldText, newText)
    const s = summarizeDiff(spans)
    console.log(`场景 ${sceneNo}  v${from} → v${to}`)
    console.log(
      `  相似度 ${(s.similarity * 100).toFixed(1)}%   新增 ${s.addedChars} 字   删除 ${s.removedChars} 字`,
    )
    const hints = renderDiffHints(spans, 40)
    if (hints.length === 0) {
      console.log('  两个版本内容完全相同')
      return
    }
    for (const h of hints) console.log(`  ${h}`)
    console.log('\n（diff 只用于展示，落库以你接受哪个版本为准）')
  })
}

  )

  console.log(`✓ 已应用 ${r.applied} 条，跳过 ${r.skipped} 条`)
  if (r.applied > 0) console.log('  已写入 EntityRevision（append-only，可回退到旧版本）')
}
```

```ts
    const newest = rows.filter((r) => r.sceneNo === 1).sort((a, b) => b.version - a.version)[0]
    if (newest === undefined) throw new Error('缺少场景 1')
    await acceptScene({ chapterNo: 4, sceneNo: 1, version: newest.version })
    const all = await listChapterScenes(4)
    const candidates = all.filter((r) => r.status === 'candidate')
    if (candidates.length > 0) throw new Error(`仍有 ${candidates.length} 个 candidate`)
  })

  // ---------------------------------------------------------------- 定稿
  let finalRel = ''
  await check('★ 定稿：合并正文 + finalized + 蓝图摘要', async () => {
    const r = await finalizeChapter({ chapterNo: 4, title: '第四章 剑冢' })
    finalRel = r.relPath
    if (r.sceneCount !== 3) throw new Error(`应合并 3 个场景，实际 ${r.sceneCount}`)
    const raw = await readFile(join(book, r.relPath), 'utf8')
    if (!raw.includes('她没躲')) throw new Error('定稿正文里缺少编辑后的内容')
    if (!raw.includes('碑上刻着她自己的名字')) throw new Error('定稿正文缺少场景 3')
    if (!r.summary.includes('走到碑前')) throw new Error(`摘要应含蓝图目标，实际 ${r.summary}`)
    if (db === null) throw new Error('db 未初始化')
    const ch = await db.chapter.findFirst({ where: { chapterNo: 4 } })
    if (ch?.status !== 'finalized') throw new Error(`Chapter 应为 finalized，实际 ${ch?.status}`)
    if (ch.finalizedAt === null) throw new Error('finalizedAt 未写')
  })

  // ---------------------------------------------------------------- 提案
  await check('★ 状态提案：只提案不落库，stateChapter=5', async () => {
    const r = await proposeStateChanges({ chapterNo: 4, apiKey: 'sk-fake', fetchImpl: llm })
    if (r.proposals.length !== 1) throw new Error(`应有 1 条提案，实际 ${r.proposals.length}`)
    const p = r.proposals[0]
    if (p?.stateChapter !== 5) throw new Error(`stateChapter 应为 5，实际 ${p?.stateChapter}`)
    if (p.characterId !== 'c1') throw new Error(`角色应为 c1，实际 ${p.characterId}`)
    const revs = await readRevisions(book, 'character', 'c1')
    if (revs.length !== 0) throw new Error('提案阶段不应写入 revision')
  })

  // ---------------------------------------------------------------- 应用
  await check('★ 应用提案：写 revision + 清 stateStale', async () => {
    const proposals = await (async () => {
      const r = await proposeStateChanges({ chapterNo: 4, apiKey: 'sk-fake', fetchImpl: llm })
      return r.proposals
    })()
    const applied = await applyStateProposals({
      chapterNo: 4,
      acceptIds: proposals.map((p) => p.id),
    })
    if (applied.applied !== 1) throw new Error(`应应用 1 条，实际 ${applied.applied}`)
    const revs = await readRevisions(book, 'character', 'c1')
    if (revs.length !== 1) throw new Error(`应有 1 条 revision，实际 ${revs.length}`)
    const payload = JSON.parse(revs[0]?.payload ?? '{}') as Record<string, unknown>
    if (payload['stateChapter'] !== 5) throw new Error('revision 的 stateChapter 应为 5')
    if (payload['curPhysical'] !== '左臂受伤') {
      throw new Error(`revision 的 curPhysical 应为 左臂受伤，实际 ${String(payload['curPhysical'])}`)
    }
  })

  // ---------------------------------------------------------------- 撤销
  await check('★ 撤销定稿：finalized → review，正文保留', async () => {
    await unfinalizeChapter({ chapterNo: 4 })
    if (db === null) throw new Error('db 未初始化')
    const ch = await db.chapter.findFirst({ where: { chapterNo: 4 } })
    if (ch?.status !== 'review') throw new Error(`Chapter 应为 review，实际 ${ch?.status}`)
    const raw = await readFile(join(book, finalRel), 'utf8')
    if (!raw.includes('碑上刻着她自己的名字')) throw new Error('撤销后正文应保留')
  })

  // ---------------------------------------------------------------- 收尾一致性
  await check('导出与 Git 一致（定稿内容在导出里）', async () => {
    const j = JSON.parse((await exportBook('json', book)).content) as {
      chapters?: { chapterNo: number; content?: string }[]
    }
    const ch4 = j.chapters?.find((c) => c.chapterNo === 4)
    if (ch4 === undefined) throw new Error('导出缺第 4 章')
    const count = Number((await git(book, ['rev-list', '--count', 'HEAD'])).trim())
    if (count < 5) throw new Error(`该有多次 commit（初始化/接受/编辑/定稿/撤销），实际 ${count}`)
    void bookPaths
  })
} finally {
  if (db !== null) await db.$disconnect().catch(() => undefined)
  await rm(tmp, { recursive: true, force: true, maxRetries: 5, retryDelay: 100 })
}

const failed = results.filter((r) => !r.ok)
console.log(`\n${results.length - failed.length}/${results.length} 通过`)
if (failed.length > 0) {
  console.error('\n未通过：')
  for (const f of failed) console.error(`  ✗ ${f.name}\n    ${f.err}`)
  process.exit(1)
}
console.log('✓ P1-b 验收全部通过')
```
