# inkloom P1-a 实现计划（生成链路）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `inkloom write --chapter N` 能对一本真实书稿生成第 N 章的场景候选稿，并把完整装配结果存档，从而第一次验证"精准装配的 prompt 是否真的比裸问模型好"。

**Architecture:** `packages/prompt` 只做纯函数装配（零 IO，零 LLM 调用），`apps/api/src/llm` 是唯一的网络出口，`generate-service` 负责编排（装载 → 装配 → 调用 → 切分 → 落盘）。Prompt 的段序是设计的一部分：S1–S5 跨章不变（命中前缀缓存），U1–U9 每章变化，锚点放**最后一条 user 消息末尾**（对抗 lost-in-the-middle）。

**Tech Stack:** 现有栈（TS 7 / Hono 已装但不用 / Prisma 6 / Vitest 5）。新增：`fetch` 直连 DeepSeek（**不引入 Vercel AI SDK**）。

**Spec:** `docs/superpowers/specs/2026-10-25-inkloom-design.md` §4.1（九步时序）、§4.2（Prompt 顺序）、§4.3（预算分档）、§4.4（压缩层 C0–C4）、§4.6（场景切分协议）

## Global Constraints

| 约束 | 值 / 规则 | 出处 |
|---|---|---|
| `prompt` 包禁止依赖 | `fs` / `fetch` / `prisma` / `hono`（和 core 同级约束） | spec §2.1 |
| `prompt` 允许依赖 | 仅 `core`、`shared` | spec §2.1 |
| Prompt 段序 | **S1→S5 在 system，U1→U9 在 user，锚点必须在最后一个 block** | spec §4.2 |
| 场景切分 | `===场景N===` → 空行+长度启发式 → 整章单场景（记 warning） | spec §4.6 |
| 不用 JSON 输出 | 中文长文本经 JSON 转义后语感显著下降 | spec §4.6 |
| 降级必须留痕 | 任何裁剪写 `degradationLog`，最终落到 `generation_run.degradedReason` | spec §4.3 |
| 温度/模型 | `deepseek-flash`（实测 1,048,576 上下文 / 393,216 输出） | 环境实测 |
| 成本记账 | `costCents` 在 `ModelProfile` 价格为空时必须记 `null`，**不得记 0** | ADR-31 |
| 单文件行数 | >300 warning，>500 CI failure | spec §9.2 |
| `exactOptionalPropertyTypes` | 可选字段赋值必须写 `...(x === undefined ? {} : { x })` | tsconfig |
| 测试 | 纯函数用 `*.test.ts`（unit），涉 IO 用 `*.int.test.ts`（integration） | 现有约定 |

### 明确不做（P1-a 的 YAGNI 清单）

| 不做 | 为什么 |
|---|---|
| HTTP 路由 | 单用户本地工具，CLI 足够（P0 的 Ruling 21 继续生效） |
| UI / diff 视图 | P1-c |
| 流式输出到终端 | 先证明质量，再优化体验；非流式更容易断言 |
| 逐场景 accept/reject | P1-b |
| 定稿与状态提案 | P1-b |
| 对照组脚本 | 用户已明确"AB 测试不搞，人工判断"（Ruling 34） |
| Vercel AI SDK | DeepSeek 是 OpenAI 兼容接口，50 行 fetch 足够；引入会带来几十个传递依赖 |
| RAG / 向量检索 | spec §4.5：1M 窗口 + 精确过滤已足够，v1 不做任何检索 |
| JEV 判断层 | spec ADR-19：Tier 2 不进 MVP |

    │   └── user.ts       U1 场地 · U2 进度 · U3 未兑现 · U4 摘要 · U5 上章结尾

    ├── budget.ts         token 估算 + 分档 + 裁剪 + degradationLog
    └── index.ts

packages/core/src/text/
└── scene-split.ts        ★ 场景切分（标记 → 启发式 → 整章），纯函数

apps/api/src/
├── llm/
│   ├── deepseek.ts       fetch 直连（流式 + 非流式），可注入 fetch 以便测试
│   └── types.ts          ChatMessage / ChatResult / LlmError
└── services/
    ├── context-loader.ts ★ 按章装载（唯一碰 IO 的地方，core/prompt 都不碰）
    └── generate-service.ts ★ 编排：装载 → 装配 → 调用 → 切分 → 落盘 → 记账

apps/cli/src/
├── commands.ts           新增 write 子命令
└── index.ts              分发 write
```

**为什么 `context-loader` 单独成文件**：spec §2.3 明确 `core/context` 只接收已装载的数组、不查库。装载是 IO，必须留在 api 层。把它独立出来，`generate-service` 才是纯编排，测试时可以替换 loader 用假数据。

```ts
export type BlockId =
  | 'S1' | 'S2' | 'S3' | 'S4' | 'S5'
  | 'U1' | 'U2' | 'U3' | 'U4' | 'U5' | 'U6' | 'U7' | 'U8' | 'U9'

export type BlockRole = 'system' | 'user'

/**
 * 预算优先级（spec §4.3）。
 * P0/P1 不裁剪（超预算走分档流程），P2–P7 按阶梯降级。
 */
export type BlockPriority = 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7

export interface PromptBlock {
  id: BlockId
  role: BlockRole
  priority: BlockPriority
  /** 渲染后的纯文本；null 表示该块本次无内容（跳过渲染，但保留槽位语义） */
  content: string | null
}
```

> **为什么 `content` 允许 null 而不是空字符串**：空字符串会让"该块不存在"和"该块内容为空"无法区分，而装配层要据此决定是否跳过该段。`null` 是明确的"无此块"。

- [ ] **Step 6: 实现 system.ts**

```ts
import type { Project, StyleAsset, WorldRule } from '@inkloom/shared'
import type { PromptBlock } from '../types.js'

/**
 * S1 角色身份与职责。
 *
 * ★ 这是 system 段的第一块，必须跨章完全一致（含标点），否则 DeepSeek 的
 *   前缀缓存全部失效（缓存命中 ¥0.04/M vs 未命中 ¥2/M，50 倍差距）。
 *   所以这里**绝不能**出现章节号、角色名等随章变化的内容。
 */
export function blockS1(project: Project): PromptBlock {
  const lines = [
    '你是一位签约于起点中文网的长篇网文作者，擅长玄幻题材。',
    `你正在写《${project.name}》这本书（题材：${project.genre}）。`,
    '你的任务是根据给定的设定、蓝图与上文，写出本章正文。',
    '你只输出正文，不解释、不评论、不写作者的话。',
  ]
  return { id: 'S1', role: 'system', priority: 0, content: lines.join('\n') }
}

/** S2 文风契约：整体语感。放 system 是因为它跨章不变 */
export function blockS2(style: StyleAsset): PromptBlock {
  const lines = ['【文风契约】', style.description]
  if (style.samples.length > 0) {
    lines.push('', '语感示例（模仿其节奏与用词密度，不要照抄内容）：')
    for (const s of style.samples) lines.push(`· ${s}`)
  }
  return { id: 'S2', role: 'system', priority: 1, content: lines.join('\n') }
}

/** S3 反 AI 规则：量化约束。无规则时返回 null（不产生空块） */
export function blockS3(style: StyleAsset): PromptBlock {
  const hasWords = style.bannedWords.length > 0
  const hasPatterns = style.bannedPatterns.length > 0
  const quantEntries = Object.entries(style.quantLimits)
  if (!hasWords && !hasPatterns && quantEntries.length === 0) {
    return { id: 'S3', role: 'system', priority: 1, content: null }
  }

  const lines = ['【反 AI 味规则】（违反即视为不合格）']
  if (hasWords) {
    lines.push(`禁用词（一次都不许出现）：${style.bannedWords.join('、')}`)
  }
  if (hasPatterns) {
    lines.push('禁用句式：')
    for (const p of style.bannedPatterns) lines.push(`· ${p}`)
  }
  if (quantEntries.length > 0) {
    lines.push('量化上限（全章合计不得超过）：')
    for (const [word, limit] of quantEntries) lines.push(`· ${word}：${limit} 次`)
  }
  lines.push(
    '',
    '另外避免：排比三连、每段都以景语开头、用“仿佛/似乎/好像”代替具体描写、',
    '用抽象情绪词（悲凉、震撼、复杂）代替具体动作与物象。',
  )
  return { id: 'S3', role: 'system', priority: 1, content: lines.join('\n') }
}

/** S4 世界 hard 规则：违背即 OOC，必须全量注入 */
export function blockS4(hardRules: WorldRule[]): PromptBlock {
  if (hardRules.length === 0) {
    return { id: 'S4', role: 'system', priority: 0, content: null }
  }
  const lines = ['【世界硬规则】（违背即视为设定崩坏）']
  for (const r of hardRules) {
    lines.push(`· [${r.category}] ${r.name}：${r.content}`)
  }
  return { id: 'S4', role: 'system', priority: 0, content: lines.join('\n') }
}

/**
 * S5 输出格式约定（spec §4.6）。
 *
 * ★ 明确禁止 JSON：中文长文本经 JSON 转义后语感显著下降，
 *   而且模型会在字符串里引入 \n 转义，下游解析成本高。
 */
export function blockS5(input: { wordsPerChapter: number | null }): PromptBlock {
  const words = input.wordsPerChapter ?? 3000
  const lines = [
    '【输出格式】',
    '只输出正文，不要任何前言、后记、解释或 Markdown 标题。',
    '',
    '用下面的标记分场景（场景是审阅单位，一般 3–6 个）：',
    '===场景1===',
    '（场景正文，场景内以空行分段）',
    '',
    '===场景2===',
    '（…）',
    '',
    `全章目标字数 ${words} 字（允许 ±20%）。`,
    '不要输出 JSON，不要用代码块包裹。',
  ]
  return { id: 'S5', role: 'system', priority: 0, content: lines.join('\n') }
}
```

import type { Blueprint, Character, CharacterRelation, CharacterSignature, Location, PlotThread, Project, Route, WorldRule } from '@inkloom/shared'
import type { PromptBlock } from '../types.js'

/** 上章结尾保留的字数上限（spec §4.4 的 C2 层） */
const PREVIOUS_ENDING_CHARS = 800

export interface ChapterContextInput {
  project: Project
  blueprint: Blueprint
  cast: Character[]
  relations: CharacterRelation[]
  tiers: { characterId: string; tierName: string; level: number }[]
  location: Location | null
  routes: Route[]
  hardRules: WorldRule[]
  softRules: WorldRule[]
  timeline: Blueprint[]
  upcoming: Blueprint[]
  unresolved: PlotThread[]
  summaries: { chapterNo: number; summary: string }[]
  previousEnding: string | null
  signatures: CharacterSignature[]
  userGuidance: string | null
}

function tierOf(input: ChapterContextInput, characterId: string): string | null {
  const t = input.tiers.find((x) => x.characterId === characterId)
  return t === undefined ? null : `${t.tierName}（第 ${t.level} 阶）`
}

/**
 * U1 本章场地设定。
 *
 * ★ 为什么 U1 不在 system：这些内容每章随 castIds 变化，
 *   放进 system 会让 S1–S5 之后的所有前缀缓存失效（spec §4.2 的审查修正）。
 */
export function blockU1(input: ChapterContextInput): PromptBlock {
  const lines = ['【本章场地设定】']

  lines.push('', '## 出场角色')
  for (const c of input.cast) {
    const bits: string[] = [`${c.name}（${c.role}）`]
    if (c.personality !== undefined) bits.push(`性格：${c.personality}`)
    if (c.motivation !== undefined) bits.push(`动机：${c.motivation}`)
    if (c.appearance !== undefined) bits.push(`外貌：${c.appearance}`)
    if (c.curPhysical !== undefined) bits.push(`当前身体：${c.curPhysical}`)
    if (c.curMental !== undefined) bits.push(`当前心境：${c.curMental}`)
    const tier = tierOf(input, c.id)
    if (tier !== null) bits.push(`修为：${tier}`)
    // visualAnchor 是防 OOC 的关键：从参考图提取的硬特征
    if (c.visualAnchor !== undefined) bits.push(`外貌锚点（不得偏离）：${c.visualAnchor}`)
    lines.push(`· ${bits.join('；')}`)

    const sigs = input.signatures.filter((s) => s.characterId === c.id && s.isActive)
    for (const s of sigs) {
      lines.push(`  - 签名[${s.kind}/${s.trigger}/${s.frequency}]：${s.content}`)
    }
  }

  if (input.relations.length > 0) {
    lines.push('', '## 角色关系')
    const nameOf = (id: string): string => input.cast.find((c) => c.id === id)?.name ?? id
    for (const r of input.relations) {
      lines.push(`· ${nameOf(r.fromId)} → ${nameOf(r.toId)}：${r.kind}（强度 ${r.strength}/5）`)
    }
  }

  if (input.location !== null) {
    lines.push('', `## 本章地点：${input.location.name}（${input.location.type}）`)
    if (input.location.region !== undefined) lines.push(`所属区域：${input.location.region}`)
    if (input.location.description !== undefined) lines.push(input.location.description)
  }

  if (input.routes.length > 0) {
    lines.push('', '## 相关路程（系统计算，不得自行更改）')
    for (const r of input.routes) {
      lines.push(`· ${r.mode}：${r.days} 天${r.condition === undefined ? '' : `（${r.condition}）`}`)
    }
  }

  if (input.softRules.length > 0) {
    lines.push('', '## 世界软设定（建议遵循）')
    for (const r of input.softRules) lines.push(`· ${r.name}：${r.content}`)
  }

  return { id: 'U1', role: 'user', priority: 1, content: lines.join('\n') }
}

/** U2 全书进度：只列到本章为止，绝不泄露后续 */
export function blockU2(input: ChapterContextInput): PromptBlock {
  const upto = input.timeline.filter((b) => b.chapterNo <= input.blueprint.chapterNo)
  if (upto.length === 0) return { id: 'U2', role: 'user', priority: 7, content: null }
  const lines = ['【全书进度】（截至本章）']
  for (const b of upto) {
    lines.push(`第 ${b.chapterNo} 章${b.title === undefined ? '' : ` ${b.title}`}：${b.goal}`)
  }
  return { id: 'U2', role: 'user', priority: 7, content: lines.join('\n') }
}

/** U3 未兑现清单：已按紧迫度排序，调用方负责排序 */
export function blockU3(input: ChapterContextInput): PromptBlock {
  if (input.unresolved.length === 0) return { id: 'U3', role: 'user', priority: 3, content: null }
  const lines = ['【必须记住的未兑现线索】']
  for (const t of input.unresolved) {
    const parts = [`[${t.kind}] ${t.title}`]
    if (t.plantedChapter !== undefined) parts.push(`埋于第 ${t.plantedChapter} 章`)
    if (t.payoffHint !== undefined) parts.push(`预期回收：${t.payoffHint}`)
    lines.push(`· ${parts.join('，')}`)
  }
  return { id: 'U3', role: 'user', priority: 3, content: lines.join('\n') }
}

/** U4 近 3 章摘要（C3 层），按章号升序 */
export function blockU4(input: ChapterContextInput): PromptBlock {
  const sorted = [...input.summaries].sort((a, b) => a.chapterNo - b.chapterNo)
  if (sorted.length === 0) return { id: 'U4', role: 'user', priority: 2, content: null }
  const lines = ['【近期剧情摘要】']
  for (const s of sorted) lines.push(`第 ${s.chapterNo} 章：${s.summary}`)
  return { id: 'U4', role: 'user', priority: 2, content: lines.join('\n') }
}

/**
 * U5 上章结尾（C2 层，固定 800 字）。
 * ★ 超长时保留**尾部**：要接续的是结尾，不是开头。
 */
export function blockU5(input: ChapterContextInput): PromptBlock {
  if (input.previousEnding === null || input.previousEnding.trim().length === 0) {
    return { id: 'U5', role: 'user', priority: 5, content: null }
  }
  const raw = input.previousEnding.trim()
  const tail = raw.length <= PREVIOUS_ENDING_CHARS
    ? raw
    : `（前文省略）${raw.slice(-PREVIOUS_ENDING_CHARS)}`
  return {
    id: 'U5',
    role: 'user',
    priority: 5,
    content: ['【上一章结尾】（必须自然接续，不要重复这段内容）', tail].join('\n'),
  }
}

/** U6 本章蓝图：结构化描述，不泄露 castIds 原始 JSON */
export function blockU6(input: ChapterContextInput): PromptBlock {
  const b = input.blueprint
  const lines = [`【本章蓝图】第 ${b.chapterNo} 章${b.title === undefined ? '' : ` ${b.title}`}`]
  lines.push(`目标：${b.goal}`)
  lines.push(`冲突：${b.conflict}`)
  if (b.turn !== undefined) lines.push(`转折：${b.turn}`)
  lines.push(`章末钩子：${b.hook}`)
  lines.push(`节奏类型：${b.beatType}，张力 ${b.tensionLevel}/5`)
  if (b.userGuidance !== undefined) lines.push(`作者备注：${b.userGuidance}`)
  return { id: 'U6', role: 'user', priority: 0, content: lines.join('\n') }
}

/** U7 后续 2 章蓝图：明确禁止提前写 */
export function blockU7(input: ChapterContextInput): PromptBlock {
  if (input.upcoming.length === 0) return { id: 'U7', role: 'user', priority: 6, content: null }
  const lines = ['【后续剧情走向】（**不要提前写**，仅用于避免本章埋下与之冲突的伏笔）']
  for (const b of input.upcoming) {
    lines.push(`第 ${b.chapterNo} 章：${b.goal}（冲突：${b.conflict}）`)
  }
  return { id: 'U7', role: 'user', priority: 6, content: lines.join('\n') }
}

/** U8 作者本章额外指导 */
export function blockU8(input: ChapterContextInput): PromptBlock {
  if (input.userGuidance === null || input.userGuidance.trim().length === 0) {
    return { id: 'U8', role: 'user', priority: 4, content: null }
  }
  return {
    id: 'U8',
    role: 'user',
    priority: 4,
    content: ['【作者本章额外指导】', input.userGuidance.trim()].join('\n'),
  }
}

/**
 * U9 锚点：不可偏离的作者事实。
 *
 * ★ 这是最后一道防线，也是**最后一个 block**。
 *   放在末尾是对抗 lost-in-the-middle：开头（S1）说一次、结尾（U9）再说一次，
 *   中间的易变内容才不会把核心设定冲掉。
 */
export function blockU9(input: ChapterContextInput): PromptBlock {
  const p = input.project
  const items: string[] = []
  if (p.coreIdea !== undefined) items.push(`核心创意：${p.coreIdea}`)
  if (p.premise !== undefined) items.push(`故事前提：${p.premise}`)
  if (p.theme !== undefined) items.push(`主题：${p.theme}`)
  if (p.toneContract !== undefined) items.push(`语调契约：${p.toneContract}`)
  if (items.length === 0) return { id: 'U9', role: 'user', priority: 0, content: null }

  const lines = ['【不可偏离的作者事实】（以下内容**不可偏离**，与之冲突的写法一律视为错误）']
  for (const it of items) lines.push(`· ${it}`)
  return { id: 'U9', role: 'user', priority: 0, content: lines.join('\n') }
}

```ts
import type { PromptBlock } from './types.js'

export interface Degradation {
  blockId: string
  action: 'trim' | 'drop' | 'reduce'
  detail: string
}

export interface BudgetConfig {
  /** 分母 = 模型上下文窗口 − 最大输出（spec §3.12.2 的 budgetDenominator） */
  denominator: number
  warnRatio: number
  promptRatio: number
  forceRatio: number
}

export type BudgetTier = 'normal' | 'warn' | 'prompt' | 'force'

const CJK_RE = /[\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff]/g

/**
 * token 估算法（保守）。
 *
 * 中文约 1.5 字/token，其它（英文/数字/标点）约 4 字符/token。
 * ★ 保守估算的意义：宁可高估导致多裁一点，也不要低估导致 API 端截断。
 */
export function estimateTokens(text: string): number {
  if (text.length === 0) return 0
  const cjk = text.match(CJK_RE)?.length ?? 0
  const other = text.length - cjk
  return Math.ceil(cjk / 1.5 + other / 4)
}

function totalTokens(blocks: PromptBlock[]): number {
  let sum = 0
  for (const b of blocks) if (b.content !== null) sum += estimateTokens(b.content)
  return sum
}

/**
 * 预算裁剪（spec §4.3）。
 *
 * 规则：
 *   - priority 0/1（P0/P1）**永不裁剪**——它们是本章能不能看的底线
 *   - priority 2..7 按**优先级从低到高**依次 drop，直到进入 promptRatio 以内
 *   - 每次 drop 都写 degradation，事后可归因
 *
 * ★ 为什么不在超预算时抛错：那会让用户卡死。
 *   降级 + 留痕是更好的选择，质量差了能查到原因。
 */
export function applyBudget(
  blocks: PromptBlock[],
  cfg: BudgetConfig,
): { blocks: PromptBlock[]; degradation: Degradation[]; tier: BudgetTier; usedRatio: number } {
  const degradation: Degradation[] = []
  let kept = [...blocks]
  let tokens = totalTokens(kept)
  let ratio = cfg.denominator > 0 ? tokens / cfg.denominator : 0

  // 从最不重要的开始裁（priority 大的先走）
  const droppable = [...kept]
    .filter((b) => b.priority >= 2 && b.content !== null)
    .sort((a, b) => b.priority - a.priority)

  for (const victim of droppable) {
    if (ratio <= cfg.promptRatio) break
    kept = kept.filter((b) => b.id !== victim.id)
    tokens = totalTokens(kept)
    ratio = cfg.denominator > 0 ? tokens / cfg.denominator : 0
    degradation.push({
      blockId: victim.id,
      action: 'drop',
      detail: `P${victim.priority} 块超出预算被丢弃（使用率降至 ${(ratio * 100).toFixed(1)}%）`,
    })
  }

  const tier: BudgetTier =
    ratio > cfg.forceRatio ? 'force' : ratio > cfg.promptRatio ? 'prompt' : ratio > cfg.warnRatio ? 'warn' : 'normal'

  return { blocks: kept, degradation, tier, usedRatio: ratio }
}
```

import type { StyleAsset } from '@inkloom/shared'
import { blockS1, blockS2, blockS3, blockS4, blockS5 } from './blocks/system.js'
import {
  blockU1, blockU2, blockU3, blockU4, blockU5, blockU6, blockU7, blockU8, blockU9,
  type ChapterContextInput,
} from './blocks/user.js'
import { applyBudget, estimateTokens, type BudgetConfig, type BudgetTier, type Degradation } from './budget.js'
import type { PromptBlock } from './types.js'

export type PromptRole = 'system' | 'user'

/**
 * 装配层自己的消息类型。
 *
 * ❗不叫 ChatMessage：`apps/api/src/llm/types.ts` 里的 ChatMessage 是含
 * `'assistant'` 的三元联合。两个同名接口并存会让实现者传错类型。
 * 结构上 PromptMessage 是 ChatMessage 的子集，赋值兼容，但名字不同。
 */
export interface PromptMessage {
  role: PromptRole
  content: string
}

export interface AssembleInput extends ChapterContextInput {
  style: StyleAsset
}

export interface AssembledPrompt {
  messages: ChatMessage[]
  /** 实际参与装配的块（含被裁剪后的结果），存档用 */
  blocks: PromptBlock[]
  tokenEstimate: number
  degradation: Degradation[]
  tier: BudgetTier
  usedRatio: number
}

/**
 * 默认预算（deepseek-flash 实测：上下文 1,048,576 / 最大输出 393,216）。
 * denominator = 1,048,576 − 393,216 = 655,360
 *
 * ★ 这个分母很大，所以 30 万字全塞也只占约 46%。
 *   分档机制在日常不会触发，它的价值是防未来接小窗口模型。
 */
export const DEFAULT_BUDGET: BudgetConfig = {
  denominator: 655_360,
  warnRatio: 0.7,
  promptRatio: 0.85,
  forceRatio: 0.95,
}

const BLOCK_SEPARATOR = '\n\n'

/**
 * 装配 Prompt（spec §4.2）。
 *
 * 顺序是设计的一部分，不是实现细节：
 *   system: S1 身份 → S2 文风 → S3 反AI → S4 hard规则 → S5 输出格式
 *   user:   U1 场地 → U2 进度 → U3 线索 → U4 摘要 → U5 上接
 *           → U6 本章蓝图 → U7 后续 → U8 指导 → U9 锚点（**必须最后**）
 *
 * ★ S1–S5 跨章完全一致 → 命中 DeepSeek 前缀缓存（¥0.04/M vs ¥2/M）。
 * ★ U9 放末尾 → 与 S1 形成首尾夹击，对抗 lost-in-the-middle。
 */
export function assemble(input: AssembleInput, cfg: BudgetConfig = DEFAULT_BUDGET): AssembledPrompt {
  const sBlocks: PromptBlock[] = [
    blockS1(input.project),
    blockS2(input.style),
    blockS3(input.style),
    blockS4(input.hardRules),
    blockS5({ wordsPerChapter: input.project.wordsPerChapter ?? null }),
  ]
  const uBlocks: PromptBlock[] = [
    blockU1(input),
    blockU2(input),
    blockU3(input),
    blockU4(input),
    blockU5(input),
    blockU6(input),
    blockU7(input),
    blockU8(input),
    blockU9(input), // ★ 必须最后
  ]

  const ordered = [...sBlocks, ...uBlocks]
  const budgeted = applyBudget(ordered, cfg)

  const render = (role: PromptRole): string =>
    budgeted.blocks
      .filter((b) => b.role === role && b.content !== null)
      .map((b) => b.content as string)
      .join(BLOCK_SEPARATOR)

  const messages: PromptMessage[] = [
    { role: 'system', content: render('system') },
    { role: 'user', content: render('user') },
  ]

  return {
    messages,
    blocks: budgeted.blocks,
    tokenEstimate: messages.reduce((n, m) => n + estimateTokens(m.content), 0),
    degradation: budgeted.degradation,
    tier: budgeted.tier,
    usedRatio: budgeted.usedRatio,
  }
}

```ts
export type SplitStrategy = 'marker' | 'heuristic' | 'whole'

export interface SplitResult {
  scenes: string[]
  strategy: SplitStrategy
  warnings: string[]
}

/** 每个场景的目标字数（启发式切分用；低于此值会与相邻场景合并） */
const TARGET_SCENE_CHARS = 400

/** 容忍 `===场景1===` / `=== 场景 1 ===` / 全角数字 */
const MARKER_RE = /^[ \t]*={2,}[ \t]*场景[ \t]*([0-9０-９]+)[ \t]*={2,}[ \t]*$/gm
const FENCE_RE = /^```[a-z]*\s*$/gm

/**
 * 场景切分（spec §4.6）。
 *
 * 降级链：标记切 → 空行+长度启发式 → 整章单场景。
 * 每一级降级都记 warning，事后能看出"模型没听话"。
 *
 * ★ 为什么不用 JSON 解析：中文长文本经 JSON 转义后语感显著下降，
 *   而且模型会在字符串里塞 \n 转义，下游还得反转义。
 */
export function splitScenes(raw: string): SplitResult {
  const warnings: string[] = []
  // 去掉模型可能加的代码块围栏
  const text = raw.replace(FENCE_RE, '').trim()

  if (text.length === 0) {
    return { scenes: [], strategy: 'whole', warnings: ['模型输出为空'] }
  }

  const markers = [...text.matchAll(MARKER_RE)]
  if (markers.length > 0) {
    const scenes: string[] = []
    for (let i = 0; i < markers.length; i++) {
      const start = (markers[i]?.index ?? 0) + (markers[i]?.[0].length ?? 0)
      const end = i + 1 < markers.length ? (markers[i + 1]?.index ?? text.length) : text.length
      const body = text.slice(start, end).trim()
      if (body.length > 0) scenes.push(body)
    }
    if (scenes.length > 0) return { scenes, strategy: 'marker', warnings }
    warnings.push('检测到场景标记但场景内容全为空')
  }

  // 降级 1：空行切分 + 长度合并
  const paragraphs = text
    .split(/\r?\n\s*\r?\n/)
    .map((p) => p.trim())
    .filter((p) => p.length > 0)

  if (paragraphs.length === 0) {
    return { scenes: [], strategy: 'whole', warnings: [...warnings, '模型输出只有空白'] }
  }

  // 极短文本不硬切
  if (text.length < TARGET_SCENE_CHARS) {
    warnings.push(`未找到场景标记，且正文仅 ${text.length} 字，整章作为单场景处理`)
    return { scenes: [text], strategy: 'whole', warnings }
  }

  const scenes: string[] = []
  let buffer: string[] = []
  let bufferChars = 0
  for (const p of paragraphs) {
    buffer.push(p)
    bufferChars += p.length
    if (bufferChars >= TARGET_SCENE_CHARS) {
      scenes.push(buffer.join('\n\n'))
      buffer = []
      bufferChars = 0
    }
  }
  if (buffer.length > 0) {
    if (scenes.length === 0) scenes.push(buffer.join('\n\n'))
    else scenes[scenes.length - 1] = `${scenes[scenes.length - 1]}\n\n${buffer.join('\n\n')}`
  }

  warnings.push(`未找到 ===场景N=== 标记，按空行+长度启发式切分为 ${scenes.length} 个场景`)
  return { scenes, strategy: 'heuristic', warnings }
}

/** 单场景正文 → 段数组（按空行切，与 markers.ts 的 splitParagraphs 同语义） */
export function toSegments(sceneText: string): string[] {
  return sceneText
    .split(/\r?\n\s*\r?\n/)
    .map((p) => p.trim())
    .filter((p) => p.length > 0)
}

- [ ] **Step 4: 实现 deepseek.ts**

```ts
import { LlmError } from './types.js'
import type { ChatMessage, ChatOptions, ChatResult, FetchLike } from './types.js'

/**
 * ★ 必须是 deepseek-flash，不是 deepseek-chat。
 *   实测：请求 deepseek-chat 会被服务端路由到 deepseek-flash，
 *   但显式写清楚能避免将来服务端改路由时静默换模型。
 */
export const DEFAULT_DEEPSEEK_MODEL = 'deepseek-flash'
export const DEFAULT_DEEPSEEK_BASE_URL = 'https://api.deepseek.com'
const DEFAULT_TIMEOUT_MS = 180_000

interface DeepSeekResponse {
  choices?: { message?: { content?: string }; finish_reason?: string }[]
  usage?: {
    prompt_tokens?: number
    completion_tokens?: number
    prompt_cache_hit_tokens?: number
  }
}

/** 从错误响应里尽量挖出可读信息，但绝不回显 apiKey */
function describeFailure(status: number, bodyText: string): string {
  try {
    const j = JSON.parse(bodyText) as { error?: { message?: string } }
    const msg = j.error?.message
    if (typeof msg === 'string' && msg.length > 0) return msg
  } catch {
    // 非 JSON，退回截断原文
  }
  return bodyText.slice(0, 200)
}

/**
 * 调用 DeepSeek Chat Completions（OpenAI 兼容）。
 *
 * 为什么不用 Vercel AI SDK：DeepSeek 是 OpenAI 兼容接口，非流式调用约 60 行；
 * 引入 `ai` + provider 包会带来几十个传递依赖，与「不要太繁重」冲突。
 * P1-a 也用不到 SDK 的结构化输出 / tool calling。
 *
 * ★ `fetchImpl` 可注入：测试时用假 fetch，CI 零网络、零花费。
 */
export async function chat(opts: ChatOptions): Promise<ChatResult> {
  const model = opts.model ?? DEFAULT_DEEPSEEK_MODEL
  const baseUrl = opts.baseUrl ?? DEFAULT_DEEPSEEK_BASE_URL
  const doFetch: FetchLike = opts.fetchImpl ?? ((url, init) => fetch(url, init))
  const timeoutMs = opts.timeoutMs ?? DEFAULT_TIMEOUT_MS

  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), timeoutMs)
  // 外部 signal 与内部超时合并：任一触发都中止
  if (opts.signal !== undefined) {
    if (opts.signal.aborted) controller.abort()
    else opts.signal.addEventListener('abort', () => controller.abort(), { once: true })
  }

  const body: Record<string, unknown> = {
    model,
    messages: opts.messages satisfies ChatMessage[],
    stream: false,
  }
  if (opts.temperature !== undefined) body['temperature'] = opts.temperature
  if (opts.maxTokens !== undefined) body['max_tokens'] = opts.maxTokens

  let res: Response
  try {
    res = await doFetch(`${baseUrl}/chat/completions`, {
      method: 'POST',
      headers: {
        authorization: `Bearer ${opts.apiKey}`,
        'content-type': 'application/json',
      },
      body: JSON.stringify(body),
      signal: controller.signal,
    })
  } catch (e) {
    clearTimeout(timer)
    const name = (e as Error).name
    if (name === 'AbortError') {
      throw new LlmError('TIMEOUT', `请求超过 ${timeoutMs}ms 未返回`)
    }
    throw new LlmError('HTTP', `网络错误：${(e as Error).message}`)
  } finally {
    clearTimeout(timer)
  }

  if (!res.ok) {
    const text = await res.text().catch(() => '')
    const detail = describeFailure(res.status, text)
    if (res.status === 401) {
      throw new LlmError('AUTH', `鉴权失败（检查 .env 里的 DEEPSEEK_API_KEY）：${detail}`, 401)
    }
    if (res.status === 429) {
      const ra = res.headers.get('retry-after')
      const sec = ra === null ? null : Number(ra)
      throw new LlmError('RATE_LIMIT', `限流：${detail}`, 429, Number.isFinite(sec) ? sec : null)
    }
    throw new LlmError('HTTP', `HTTP ${res.status}：${detail}`, res.status)
  }

  const json = (await res.json()) as DeepSeekResponse
  const content = json.choices?.[0]?.message?.content ?? ''
  if (content.trim().length === 0) {
    throw new LlmError('EMPTY', '模型返回空内容（不落候选稿）')
  }

  return {
    content,
    usage: {
      input: json.usage?.prompt_tokens ?? 0,
      output: json.usage?.completion_tokens ?? 0,
      cacheHit: json.usage?.prompt_cache_hit_tokens ?? 0,
    },
    finishReason: json.choices?.[0]?.finish_reason ?? 'unknown',
  }
}
```

> ✅ 文件末尾**没有** re-export：`deepseek.ts` 只暴露 `chat` 与 `DEFAULT_DEEPSEEK_MODEL` / `DEFAULT_DEEPSEEK_BASE_URL` 两个常量。
> 调用方从 `./types.js` 拿 `LlmError` / `FetchLike` / `ChatMessage`——同一个类永远只有一个导入路径，不会出现“两个 LlmError”导致的 `instanceof` 失效。

import { join } from 'node:path'
import { resolveCharacterState } from '@inkloom/core'
import type { AssembleInput } from '@inkloom/prompt'
import {
  type Blueprint, type Character, type CharacterRelation, type CharacterSignature,
  InkloomError, type Location, type PlotThread, type Project, type Route, type StyleAsset,
  type WorldRule, blueprintSchema, characterRelationSchema, characterSchema, characterSignatureSchema,
  locationSchema, plotThreadSchema, projectSchema, routeSchema, styleAssetSchema, worldRuleSchema,
} from '@inkloom/shared'
import { readIfExists } from '../storage/atomic-write.js'
import { readJsonArray, readJsonElement } from '../storage/elements.js'
import { bookPaths } from '../storage/paths.js'
import { readRevisions } from '../storage/revisions.js'
import { getContext } from './context.js'

/** 上章结尾取多少字（spec §4.4 的 C2 层固定 800） */
const PREVIOUS_ENDING_CHARS = 800
/** 近期摘要取几章（C3 层） */
const SUMMARY_CHAPTERS = 3

export interface LoadedChapterContext {
  input: AssembleInput
  hasPreviousChapter: boolean
}

function rec(v: unknown): Record<string, unknown> {
  return typeof v === 'object' && v !== null ? (v as Record<string, unknown>) : {}
}

/**
 * Zod schema 的最小形状。
 * ❗不能用 `{ safeParse: (v) => { success: boolean; data?: T } }`：
 *   Zod 的失败分支没有 `data` 字段，那个签名会让所有 schema 报类型不匹配。
 */
type Parseable<T> = {
  safeParse: (v: unknown) => { success: true; data: T } | { success: false; error: unknown }
}

/** 用 Zod 逐个校验，坏数据报出确切位置而不是污染 prompt */
function parseList<T>(raw: unknown[], schema: Parseable<T>, label: string): T[] {
  const out: T[] = []
  for (const item of raw) {
    const r = schema.safeParse(item)
    if (r.success) out.push(r.data)
    else console.warn(`[context] ${label} 有一条数据不合 schema，已跳过`)
  }
  return out
}

async function readOptional<T>(
  root: string,
  rel: string,
  schema: Parseable<T>,
): Promise<T | null> {
  const raw = await readJsonElement(root, rel)
  if (raw === null) return null
  const r = schema.safeParse(raw)
  return r.success ? r.data : null
}

/**
 * 按章装载上下文（spec §4.1 第 2 步）。
 *
 * ★ 这是唯一碰 IO 的装载点。core / prompt 都只接收已装载的数组。
 * ★ 只装本章需要的：角色按 castIds 过滤，规则按 hard/soft 分开，
 *   时间线只取到本章，后续蓝图只取 2 章。全书 300 章时不装载全书。
 */
export async function loadChapterContext(
  chapterNo: number,
  opts: { userGuidance?: string } = {},
): Promise<LoadedChapterContext> {
  const { root, db, project } = getContext()
  const paths = bookPaths(root)

  // 1. 蓝图（必须先存在）
  const bpRel = `story/blueprints/ch-${String(chapterNo).padStart(3, '0')}.json`
  const blueprint = await readOptional(root, bpRel, blueprintSchema)
  if (blueprint === null) {
    throw new InkloomError('NOT_FOUND', `第 ${chapterNo} 章还没有蓝图（${bpRel}），请先建蓝图`)
  }

  // 2. 全部蓝图（用于时间线 + 后续）
  const allBlueprints: Blueprint[] = []
  const bpDir = join(paths.story, 'blueprints')
  try {
    const { readdir } = await import('node:fs/promises')
    for (const name of await readdir(bpDir)) {
      if (!name.endsWith('.json')) continue
      const b = await readOptional(root, `story/blueprints/${name}`, blueprintSchema)
      if (b !== null) allBlueprints.push(b)
    }
  } catch {
    // 目录不存在时只有本章一份
    allBlueprints.push(blueprint)
  }
  allBlueprints.sort((a, b) => a.chapterNo - b.chapterNo)

  // 3. 角色：只取 castIds，且状态按章推导
  const rawChars = await readJsonArray(root, 'characters/index.json')
  const allChars = parseList<Character>(rawChars, characterSchema, 'characters/index.json')
  const cast: Character[] = []
  for (const id of blueprint.castIds) {
    const base = allChars.find((c) => c.id === id)
    if (base === undefined) {
      console.warn(`[context] castIds 里的 ${id} 在 characters/index.json 中不存在`)
      continue
    }
    // 状态推导：按 stateChapter 取"从第 N 章起生效"的那条
    const revs = await readRevisions(root, 'character', id)
    const snap = resolveCharacterState(revs, id, chapterNo)
    const dynamic = snap === null
      ? {}
      : {
          ...(typeof snap.state['curPhysical'] === 'string' ? { curPhysical: snap.state['curPhysical'] } : {}),
          ...(typeof snap.state['curMental'] === 'string' ? { curMental: snap.state['curMental'] } : {}),
          ...(typeof snap.state['curTierId'] === 'string' ? { curTierId: snap.state['curTierId'] } : {}),
        }
    cast.push({ ...base, ...dynamic })
  }

  // 4. 关系：只取 cast 内部的关系，且在本章生效
  const rawRelations = await readJsonArray(root, 'characters/relations.json')
  const allRelations = parseList<CharacterRelation>(rawRelations, characterRelationSchema, 'characters/relations.json')
  const castIds = new Set(cast.map((c) => c.id))
  const relations = allRelations.filter(
    (r) =>
      castIds.has(r.fromId) &&
      castIds.has(r.toId) &&
      (r.sinceChapter === undefined || r.sinceChapter <= chapterNo) &&
      (r.untilChapter === undefined || r.untilChapter > chapterNo),
  )

  // 5. 签名：只取出场角色的、active 的
  const rawSigs = await readJsonArray(root, 'characters/signatures.json')
  const allSigs = parseList<CharacterSignature>(rawSigs, characterSignatureSchema, 'characters/signatures.json')
  const signatures = allSigs.filter((s) => castIds.has(s.characterId) && s.isActive)

  // 6. 规则：hard 全取、soft 全取（P1-a 不做关键词匹配，量小）
  const rawRules = await readJsonArray(root, 'world/rules.json')
  const allRules = parseList<WorldRule>(rawRules, worldRuleSchema, 'world/rules.json')
  const hardRules = allRules.filter((r) => r.priority === 'hard')
  const softRules = allRules.filter((r) => r.priority === 'soft')

  // 7. 地点与路线
  const rawLocations = await readJsonArray(root, 'world/locations.json')
  const locations = parseList<Location>(rawLocations, locationSchema, 'world/locations.json')
  const location = blueprint.locationId === undefined
    ? null
    : (locations.find((l) => l.id === blueprint.locationId) ?? null)
  const rawRoutes = await readJsonArray(root, 'world/routes.json')
  const allRoutes = parseList<Route>(rawRoutes, routeSchema, 'world/routes.json')
  const routes = location === null ? [] : allRoutes.filter((r) => r.toId === location.id)

  // 8. 线索：只取 active 且已埋设的
  const rawThreads = await readJsonArray(root, 'story/threads.json')
  const allThreads = parseList<PlotThread>(rawThreads, plotThreadSchema, 'story/threads.json')
  const unresolved = allThreads
    .filter((t) => t.status === 'active' && (t.plantedChapter === undefined || t.plantedChapter < chapterNo))
    // 紧迫度：有 payoffWindow 且已接近的排前面，其余按埋设章升序
    .sort((a, b) => {
      const aUrgent = a.payoffWindow === undefined ? Number.MAX_SAFE_INTEGER : a.payoffWindow - chapterNo
      const bUrgent = b.payoffWindow === undefined ? Number.MAX_SAFE_INTEGER : b.payoffWindow - chapterNo
      if (aUrgent !== bUrgent) return aUrgent - bUrgent
      return (a.plantedChapter ?? 0) - (b.plantedChapter ?? 0)
    })

  // 9. 近期摘要（C3 层）：从索引读，跳过 stale
  const chapterRows = await db.chapter.findMany({
    where: { projectId: project.id, chapterNo: { lt: chapterNo }, status: 'finalized', summaryStale: false },
    orderBy: { chapterNo: 'desc' },
    take: SUMMARY_CHAPTERS,
    select: { chapterNo: true, summary: true },
  })
  const summaries = chapterRows
    .filter((r): r is { chapterNo: number; summary: string } => r.summary !== null)
    .map((r) => ({ chapterNo: r.chapterNo, summary: r.summary }))

  // 10. 上章结尾（C2 层）：读定稿文件尾部
  let previousEnding: string | null = null
  if (chapterNo > 1) {
    const prevName = `ch-${String(chapterNo - 1).padStart(3, '0')}.md`
    const raw = await readIfExists(join(paths.chapters, prevName))
    if (raw !== null) {
      // 去 HTML 注释（场景/段标记）与一级标题行
      const body = raw.replace(/<!--[\s\S]*?-->/g, '').replace(/^#.*$/m, '').trim()
      previousEnding = body.length <= PREVIOUS_ENDING_CHARS ? body : body.slice(-PREVIOUS_ENDING_CHARS)
    }
  }

  // 11. 文风：取 isDefault 的那套
  const style = await readOptional(root, 'styles/default.json', styleAssetSchema)
  if (style === null) {
    throw new InkloomError('NOT_FOUND', 'styles/default.json 不存在或不合规，无法确定文风')
  }

  // 12. tier（P1-a 从角色 curTierId 反查：力量体系文件可选）
  const tiers: { characterId: string; tierName: string; level: number }[] = []
  const ps = rec((await readJsonElement(root, 'world/power-system.json')) ?? {})
  const tierList = Array.isArray(ps['tiers']) ? (ps['tiers'] as unknown[]) : []
  for (const c of cast) {
    if (c.curTierId === undefined) continue
    const t = tierList.map(rec).find((x) => x['id'] === c.curTierId)
    if (t === undefined) continue
    tiers.push({
      characterId: c.id,
      tierName: String(t['name'] ?? ''),
      level: typeof t['level'] === 'number' ? t['level'] : 0,
    })
  }

  const proj: Project = projectSchema.parse(project)

  const input: AssembleInput = {
    style,
    project: proj,
    blueprint,
    cast,
    relations,
    tiers,
    location,
    routes,
    hardRules,
    softRules,
    timeline: allBlueprints.filter((b) => b.chapterNo <= chapterNo),
    upcoming: allBlueprints.filter((b) => b.chapterNo > chapterNo).slice(0, 2),
    unresolved,
    summaries,
    previousEnding,
    signatures,
    userGuidance: opts.userGuidance ?? null,
  }

  return { input, hasPreviousChapter: previousEnding !== null }
}

```ts
import { randomUUID } from 'node:crypto'
import {
  collectChapterSegIds, countWords, newSegId, splitScenes, toSegments, type SceneFile,
} from '@inkloom/core'
import { DEFAULT_BUDGET, assemble } from '@inkloom/prompt'
import { commitAll } from '../git/runner.js'
import { chat } from '../llm/deepseek.js'
import { LlmError, type FetchLike } from '../llm/types.js'
import { hashContent } from '../storage/atomic-write.js'
import { latestSceneVersion, writeSceneFile } from '../storage/scenes.js'
import { getContext } from './context.js'
import { loadChapterContext } from './context-loader.js'

export interface GenerateChapterOptions {
  chapterNo: number
  apiKey: string
  model?: string
  userGuidance?: string
  temperature?: number
  fetchImpl?: FetchLike
}

export interface GeneratedScene {
  sceneNo: number
  version: number
  relPath: string
  wordCount: number
  segCount: number
}

export interface GenerateChapterResult {
  runId: string
  chapterNo: number
  strategy: 'marker' | 'heuristic' | 'whole'
  scenes: GeneratedScene[]
  tokenEstimate: number
  usage: { input: number; output: number; cacheHit: number }
  warnings: string[]
  degradedReason: string | null
}

function newRunId(): string {
  return `run_${randomUUID().replace(/-/g, '').slice(0, 16)}`
}

/**
 * 生成一章（spec §4.1 九步）。
 *
 * 顺序不可换：
 *   1 装载 → 2 装配 → 3 建 run（先建，失败也有记录）
 *   → 4 调 LLM → 5 切分 → 6 落候选稿 + 索引 → 7 更新 run → 8 Git commit
 *
 * ★ run 必须在调 LLM **之前**建：否则模型超时/失败时没有任何记录，
 *   事后无法知道"那次到底发了什么 prompt"。
 * ★ 但装载失败要在建 run **之前**：蓝图都没有的请求不该留下垃圾 run。
 * ★ 候选稿必须进 Git（第 8 步）：正文历史归 Git，不 commit 等于没有版本。
 */
export async function generateChapter(opts: GenerateChapterOptions): Promise<GenerateChapterResult> {
  const { root, db, project } = getContext()

  // 1. 装载（失败直接抛，不留 run）
  const loaded = await loadChapterContext(opts.chapterNo, {
    ...(opts.userGuidance === undefined ? {} : { userGuidance: opts.userGuidance }),
  })

  // 2. 装配
  const assembled = assemble(loaded.input, DEFAULT_BUDGET)

  // 3. 建 run
  const runId = newRunId()
  const model = opts.model ?? 'deepseek-flash'
  await db.generationRun.create({
    data: {
      id: runId,
      projectId: project.id,
      chapterNo: opts.chapterNo,
      commitState: 'pending',
      purpose: 'draft',
      provider: 'deepseek',
      model,
      params: JSON.stringify({ temperature: opts.temperature ?? null }),
      assembledPrompt: JSON.stringify(assembled.messages),
      tokenEstimate: assembled.tokenEstimate,
      status: 'running',
    },
  })

  // 4. 调 LLM
  let content: string
  let usage: { input: number; output: number; cacheHit: number }
  try {
    const r = await chat({
      apiKey: opts.apiKey,
      model,
      messages: assembled.messages,
      ...(opts.temperature === undefined ? {} : { temperature: opts.temperature }),
      ...(opts.fetchImpl === undefined ? {} : { fetchImpl: opts.fetchImpl }),
    })
    content = r.content
    usage = r.usage
  } catch (e) {
    const msg = e instanceof LlmError ? `${e.code}: ${e.message}` : (e as Error).message
    await db.generationRun.update({
      where: { id: runId },
      data: { status: 'failed', errorMessage: msg, finishedAt: new Date() },
    })
    throw e
  }

  // 5. 切分
  const split = splitScenes(content)

  // 6. 落候选稿 + 索引
  const taken = await collectChapterSegIds(root, opts.chapterNo)
  const scenes: GeneratedScene[] = []
  const warnings = [...split.warnings]

  for (let i = 0; i < split.scenes.length; i++) {
    const sceneNo = i + 1
    const paragraphs = toSegments(split.scenes[i] ?? '')
    if (paragraphs.length === 0) {
      warnings.push(`场景 ${sceneNo} 内容为空，已跳过`)
      continue
    }
    const segments = paragraphs.map((text) => {
      const segId = newSegId(Math.random, taken)
      taken.add(segId)
      return { segId, text }
    })

    // 场景版本 = 该场景已有最大版本 + 1（直接问文件，不靠索引反解）
    const latest = await latestSceneVersion(root, opts.chapterNo, sceneNo)
    const version = (latest ?? 0) + 1

    const scene: SceneFile = { sceneNo, version, segments }
    const { relPath } = await writeSceneFile(root, scene, opts.chapterNo)

    await db.draftSegment.createMany({
      data: segments.map((s, seq) => ({
        id: `seg_${opts.chapterNo}_${sceneNo}_${version}_${s.segId}`,
        projectId: project.id,
        chapterNo: opts.chapterNo,
        sceneNo,
        segId: s.segId,
        seq,
        filePath: relPath,
        // ★ 每段自己的 hash，不是整场景文件的 hash（spec §3.9：contentHash 是「该段」的）
        contentHash: hashContent(s.text),
        wordCount: countWords(s.text),
        status: 'candidate',
        sourceRunId: runId,
      })),
    })

    scenes.push({
      sceneNo,
      version,
      relPath,
      wordCount: segments.reduce((n, s) => n + countWords(s.text), 0),
      segCount: segments.length,
    })
  }

  // 7. 更新 run
  const degradedReason = assembled.degradation.length > 0
    ? assembled.degradation.map((d) => `${d.blockId}:${d.action}`).join(',')
    : split.strategy !== 'marker'
      ? `scene_split_fallback:${split.strategy}`
      : null

  await db.generationRun.update({
    where: { id: runId },
    data: {
      status: 'success',
      output: content,
      usageInput: usage.input,
      usageOutput: usage.output,
      cacheHitTokens: usage.cacheHit,
      commitState: 'committed',
      degradedReason,
      warnings: warnings.length > 0 ? JSON.stringify(warnings) : null,
      finishedAt: new Date(),
    },
  })

  // 8. 候选稿进 Git（spec §2.6 写入顺序第 5 步）
  await commitAll(root, `feat(scene): 第 ${opts.chapterNo} 章生成 ${scenes.length} 个场景候选`)

  return {
    runId,
    chapterNo: opts.chapterNo,
    strategy: split.strategy,
    scenes,
    tokenEstimate: assembled.tokenEstimate,
    usage,
    warnings,
    degradedReason,
  }
}

/** inkloom write <dir> --chapter N [--guidance "…"] [--model "…"] */
export async function write({ positional, flags }: CommandCtx): Promise<void> {
  const dir = requirePositional(
    positional,
    0,
    'inkloom write <dir> --chapter N [--guidance "…"] [--model "…"]',
  )
  const chapterNo = Number(requireFlag(flags, 'chapter'))
  if (!Number.isInteger(chapterNo) || chapterNo < 1) throw new Error('--chapter 必须是正整数')

  const apiKey = process.env['DEEPSEEK_API_KEY']
  if (apiKey === undefined || apiKey.trim().length === 0) {
    throw new Error('缺少 DEEPSEEK_API_KEY。复制 .env.example 为 .env 并填入 key，或设置同名环境变量')
  }

  const r = await withBook(dir, () =>
    generateChapter({
      chapterNo,
      apiKey,
      ...(flags['guidance'] === undefined ? {} : { userGuidance: flags['guidance'] }),
      ...(flags['model'] === undefined ? {} : { model: flags['model'] }),
    }),
  )

  console.log(`✓ 第 ${chapterNo} 章已生成（${r.strategy} 切分，${r.scenes.length} 个场景）`)
  console.log(`  runId        = ${r.runId}`)
  console.log(`  token 估算   = ${r.tokenEstimate}`)
  console.log(`  usage        = 输入 ${r.usage.input} / 输出 ${r.usage.output} / 缓存命中 ${r.usage.cacheHit}`)
  if (r.degradedReason !== null) console.log(`  ⚠ 降级       = ${r.degradedReason}`)
  for (const w of r.warnings) console.log(`  ⚠ ${w}`)
  for (const s of r.scenes) {
    console.log(`  场景 ${s.sceneNo}  v${s.version}  ${s.wordCount} 字 / ${s.segCount} 段  → ${s.relPath}`)
  }
}
```

// P1-a 验收：用假 LLM 跑完整链路，验证"装配 → 切分 → 落盘 → 记账"闭环。

const results: { name: string; ok: boolean; err?: string }[] = []

async function check(name: string, fn: () => Promise<void>): Promise<void> {
  try {
    await fn()
    results.push({ name, ok: true })
    console.log(`✓ ${name}`)
  } catch (e) {
    const err = e instanceof Error ? e.message : String(e)
    results.push({ name, ok: false, err })
    console.error(`✗ ${name}\n    ${err}`)
  }

const THREE_SCENES = `===场景1===
林岚踏上山道，风从袖口灌进来。

===场景2===
剑冢在雾中显现。

===场景3===
她按住了玉牌，指节泛白。`

function fakeLlm(): FetchLike {
  return async () =>
    new Response(
      JSON.stringify({
        choices: [{ message: { content: THREE_SCENES }, finish_reason: 'stop' }],
        usage: { prompt_tokens: 2100, completion_tokens: 600, prompt_cache_hit_tokens: 1800 },
      }),
      { status: 200, headers: { 'content-type': 'application/json' } },
    )
}

const tmp = await mkdtemp(join(tmpdir(), 'inkloom-p1a-'))
